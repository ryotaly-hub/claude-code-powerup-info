今日の号は v2.1.288 のアップデートから、セキュリティと日常の使い勝手に関わる修正をまとめて取り上げる。`bypassPermissions` モードやシェルの allow ルール下で危険な `rm` が確認なしに実行されてしまう不具合、パス指定の `.claude/rules` やネストした CLAUDE.md が `Write`/`Edit` では読み込まれていなかった不具合、サンドボックス自動許可中のヒアドキュメントが毎回確認を求めていた不具合、LSP が応答しないサーバーで無限にハングしていた不具合を紹介する。あわせて v2.1.289 で直った、VS Code の意図しないサインアウトとプラグインによる MCP サインインツール説明書き換えの不具合にも触れる。

この号の内容

  1. `bypassPermissions` モードやシェル allow ルール下で、危険な `rm` が確認なしに実行されていた不具合を修正（v2.1.288）

  3. サンドボックス自動許可中、クオートなしのヒアドキュメントが単純な内容なら毎回確認を求めなくなった（v2.1.288）
  4. LSP ツール呼び出しが応答しないサーバーで無限にハングする不具合を修正、60秒でタイムアウトするように（`requestTimeout`、v2.1.288）
  5. VS Code で頻発していた意図しないサインアウトの原因だった、2.1.288 の `claude auth status` への変更をロールバック（v2.1.289）
  6. ユーザーインストールのプラグインが、組織管理 MCP サーバーのサインインツールの説明文を書き換えられる不具合を修正（v2.1.289）
注意点

`bypassPermissions` モードやシェル allow ルール下で、危険な `rm` が確認なしに実行されていた不具合を修正（v2.1.288）

bash -c や sh -c に包んだスクリプトの中に / やホームディレクトリを対象にするような危険な rm があった場合、bypassPermissions モードや Bash のシェル allow ルールが効いている状態では、通常なら止まるはずの確認が素通りして実行されてしまう不具合があった。スクリプトの外側だけをルールで見ていて、bash -c "..." の中身まで見ていなかったことが原因。GitHub Issue #96300 として報告され、v2.1.288 で修正された。

つまりこう使う

  • CI や自動化スクリプトで bypassPermissions モードや Bash の allow ルールを使っている場合は、v2.1.288 以降に更新してから使う
  • bash -c 経由で rm を含むスクリプトを実行させる構成になっていないか、既存の allow ルールを一度見直す

  • anthropics/claude-code#96300
Tips

パス指定の `.claude/rules` やネストした CLAUDE.md が、`Write`/`Edit` でファイルを作成・変更したときも読み込まれるように（v2.1.288）

これまで、パスに応じて効く .claude/rules やサブディレクトリに置いたネストした CLAUDE.md は、そのパス配下のファイルを Read したときにしか読み込まれていなかった。Write や Edit で該当パスのファイルを新規作成・変更しても、読み込みが起きないまま編集だけが進むケースがあった。v2.1.288 で、Write/Edit でも同じように読み込まれるように修正された。

つまりこう使う

  • 特定ディレクトリ配下にだけ効かせたいルールを .claude/rules やネストした CLAUDE.md で運用しているなら、v2.1.288 以降では新規ファイル作成時からそのルールが効く前提で設計し直せる
  • 「読んでいないファイルを書くときはルールが効かない」という前提で Read を挟んでいた回避策があれば、不要になったので外してよい
  • Claude Code Changelog
Tips

サンドボックス自動許可中、クオートなしのヒアドキュメントが単純な内容なら毎回確認を求めなくなった（v2.1.288）

python3 <<EOF のようにデリミタをクオートしないヒアドキュメントは、本文がプレーンテキストと単純な $VAR 参照だけであっても、サンドボックス自動許可の下で毎回確認を求められていた。v2.1.288 でこの誤判定が修正され、単純なヒアドキュメントは確認なしで実行できるようになった。

つまりこう使う

  • python3 <<EOF や cat <<EOF のようなヒアドキュメントを使うスクリプトを自動許可配下で動かしていて確認が何度も出ていたなら、v2.1.288 に上げて挙動を確認する
  • 複雑な式やコマンド置換を本文に含むヒアドキュメントは対象外なので、そういうケースでは引き続き確認が出る点は押さえておく
  • Claude Code Changelog
ワークフロー

LSP ツール呼び出しが応答しないサーバーで無限にハングする不具合を修正、60秒でタイムアウトするように（`requestTimeout`、v2.1.288）

言語サーバーが動的な capability registration を使っていたり応答を止めてしまったりすると、LSP ツール呼び出しが無限にハングすることがあった。v2.1.288 で、サーバーごとに設定できる requestTimeout（デフォルト60秒）でタイムアウトするようになり、ハングしたまま固まることがなくなった。

つまりこう使う

  • LSP を使っていてツール呼び出しが固まる場面に遭遇していたら、v2.1.288 に更新する
  • 特定の言語サーバーの応答が遅く60秒では短い場合は、サーバー設定で requestTimeout を伸ばす
  • Claude Code Changelog
注意点

VS Code で頻発していた意図しないサインアウトの原因だった、2.1.288 の `claude auth status` への変更をロールバック（v2.1.289）

v2.1.288 で claude auth status に入った変更が、VS Code 拡張でのサインアウトを以前より頻繁に発生させてしまう可能性があった。v2.1.289 でこの変更はロールバックされた。v2.1.288 を使っていた間にログインが急に切れる体験をしていたなら、この変更が原因だった可能性がある。

つまりこう使う

  • VS Code 拡張を使っていて最近サインアウトが増えたと感じていたら、v2.1.289 以降に更新する
  • Claude Code Changelog
エコシステム

ユーザーインストールのプラグインが、組織管理 MCP サーバーのサインインツールの説明文を書き換えられる不具合を修正（v2.1.289）

組織が管理している MCP サーバーのサインイン用ツールについて、ユーザーが個人でインストールしたプラグインがその説明文（description）を書き換えられる状態になっていた。組織側で統制しているはずの認証フローの見え方が、ユーザー側のプラグインによって変えられてしまう余地があったことになる。v2.1.289 で修正された。

つまりこう使う

  • 組織管理の MCP サーバーを使っている Team / Enterprise 環境では、v2.1.289 以降に更新して、サインインツールの説明文がプラグインの影響を受けない状態になっているか確認する
  • Claude Code Changelog
