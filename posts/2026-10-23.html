注意点

`claude ultrareview` の実行にワークスペース信頼が必須に

claude ultrareview はワークスペースが信頼済みであることを要求するようになった。CI など非対話環境から呼んでいる場合、これまで通りには動かなくなる。

信頼チェックを通すには --trust-workspace フラグを付けるか、環境変数 CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 を設定する。

つまりこう使う

  • CI / スクリプトから claude ultrareview を呼んでいるなら、コマンドに --trust-workspace を足す
  • 恒常的に無効化したい場合は CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 を実行環境の環境変数に追加する
  • Claude Code changelog (v2.1.309)
新機能

bypass permissions モードでも危険な rm / rmdir は即座に拒否されるように

Desktop アプリと VS Code 拡張の bypass permissions モードで、rm や rmdir の危険なコマンド（マウントドライブ丸ごと削除など）を実行しようとすると、確認を挟まず即座に拒否されるようになった。拒否時には安全な書き換え案（rewrite hint）も表示される。

bypass permissions は本来すべての確認をスキップするモードだが、破壊的なファイル削除だけは例外的にブロックされる。

つまりこう使う

  • bypass permissions モードで rm -r 系のコマンドが拒否されたら、表示される rewrite hint の提案（対象を絞ったパス指定など）に従って書き直す
  • Claude Code changelog (v2.1.309)
Tips

`sed -i` が通常の Bash コマンドとして扱われ、`/rewind` では戻らなくなった

これまで特別扱いされていた sed -i が、他の Bash コマンドと同じ標準の実行確認プロンプトを経て、書いた通りに実行されるようになった。他の Bash 経由のファイル編集と同様、/rewind では元に戻せない点に注意。

つまりこう使う

  • sed -i でファイルを書き換える前に、必ず対象ファイルをコミット済みにしておく（/rewind で戻せないため）
  • 確実に戻したい変更は Edit ツールや git 管理下での作業に寄せる
  • Claude Code changelog (v2.1.309)
ワークフロー

`/claude-api` の Managed Agents が `multiagent_20261001` 構成をデフォルトで使用

/claude-api スキルが生成する Managed Agents のサブエージェントチームは、デフォルトで multiagent_20261001 構成でビルドされるようになった。また同スキルはサービスアカウントキーや Workload Identity Federation（WIF）トークンを使って OpenTelemetry の送信先を管理できるようになった。

つまりこう使う

  • Managed Agents でマルチエージェント構成を組むときは、/claude-api スキルを呼べば multiagent_20261001 ベースの構成が自動で選ばれる
  • サービスアカウントキーや WIF トークンで OTel 送信先を切り替えたい場合も /claude-api スキル経由で設定できる
  • Claude Code changelog (v2.1.309)
エコシステム

標準バンドルの dataviz スキルが APCA コントラスト測定に対応

グラフやダッシュボードを作る際に使う dataviz スキルが、テキストコントラストの指標として APCA（Advanced Perceptual Contrast Algorithm）を受け付けるようになり、apca(text, background) というバリデータ関数が追加された。WCAG のコントラスト比より知覚特性に沿った判定ができる。

つまりこう使う

  • Claude にグラフ・ダッシュボードを作らせるとき、配色のコントラスト確認を apca(text, background) で行うよう指示すると、より正確な可読性チェックになる
  • Claude Code changelog (v2.1.309)
