新機能

Anthropicホストのクラウドセッションが、リポジトリを選ばずに起動できるように

v2.1.318 で追加。これまでクラウドセッションを開始するには必ずリポジトリを1つ選ぶ必要があったが、「No repository」を選べば何もリポジトリに紐づけずにセッションを開始できるようになった。質問だけしたい、調べ物だけしたい、まだどのリポジトリで作業するか決まっていない、といったケースに向く。

つまりこう使う

  • claude.aiやClaude Code webでクラウドセッションを新規作成するとき、リポジトリ選択画面で「No repository」を選べば、リポジトリ無しのまま会話を始められる。あとで必要になればadd_repo相当の操作でリポジトリを追加すればよい。

Tips

クラウドセッションの組み込みChromiumが、`google-chrome`やWebブラウザ名、`CHROME_PATH`から見つかるように

v2.1.318 で追加。クラウドセッションにはPlaywright用のChromiumが事前にインストールされているが、これまではPlaywright経由でしか使いやすくなかった。今回、一般的なChromeの呼び名やCHROME_PATH環境変数からもこのChromiumを見つけられるようになったため、PuppeteerやLighthouseなど、Playwright以外のツールからも同じブラウザバイナリを使える。

つまりこう使う

  • クラウドセッションでPuppeteerやLighthouseを動かしたいときは、インストール済みのChromiumをCHROME_PATH経由で指定できる。ヘッドレスで動かす都合上、起動オプションに--headless --no-sandboxを付ける点は変わらない。
  • Claude Code changelog (v2.1.318)
ワークフロー

実行中のバックグラウンドエージェントへのSendMessageが、シェルコマンドを止めずに早く届くように

v2.1.317 で変更。別のセッションやエージェントからバックグラウンドエージェントへSendMessageでメッセージを送ったとき、そのエージェントが長いシェルコマンドを実行中だと、以前はコマンドの完了を待ってからメッセージが届いていた。変更後は実行中のコマンドをバックグラウンドに移すだけで止めずに、メッセージをすぐ届けるようになった。

つまりこう使う

  • 複数エージェントを並行させて途中で方針変更や追加指示を送るような運用をしている場合、相手が長いビルドやテストの最中でも、指示がそのコマンドの終了を待たずに伝わるようになった。特に設定変更は不要。
  • Claude Code changelog (v2.1.317)
Tips

Readツールの「前回Read時から変更なし」スタブ表示が廃止され、同じファイルを再読み込みすると内容がそのまま返るように

v2.1.317 で変更。これまでRead済みで変更のないファイルを再度Readすると、内容の代わりに「変更なし」という旨のスタブ文字列だけが返っていた。この挙動が廃止され、変更の有無に関わらず常にファイルの内容がそのまま返るようになった。

つまりこう使う

  • 同じファイルを何度もReadして内容を確認し直す場面で、以前は「変更なし」としか返ってこず内容を思い出すしかなかったが、今後は毎回ちゃんと中身が見られる。読み直しを避けて会話を圧縮したい場合は、この挙動変化を前提に考え直す必要がある。
  • Claude Code changelog (v2.1.317)
注意点

`/schedule`で新しいクラウド定期タスクが意図しないコネクタを持つと警告するように

v2.1.317 で追加。/scheduleでクラウドの定期実行タスクを新規作成する際、そのタスクに自分が明示的に要求していないコネクタ（Slack・GitHubなどのMCP連携）が付いてしまう場合、警告が表示されるようになった。警告には、不要なコネクタを外す方法も案内される。

つまりこう使う

  • 定期実行のRoutineを/scheduleで組むときは、警告が出たら無視せずに確認する。意図しないコネクタがそのまま定期実行に残ると、想定外のSlack投稿やGitHub操作につながりかねないため、警告に従って不要なものは外す。
  • Claude Code changelog (v2.1.317)
注意点

Webツールやシェルツールがアカウントのメールアドレスをネットワークに送ろうとすると、事前に確認を求めるように

v2.1.317 で追加。WebFetchやBashなどのツール呼び出しが、ユーザーのアカウントメールアドレスをリクエストヘッダやURL、ペイロードなどとして外部に送信しよううとする場合、実行前に確認が入るようになった。意図しないメールアドレスの漏洩を防ぐための安全策。

つまりこう使う

  • メールアドレスを送る確認が出たら、本当にそのサービスに送る必要があるものか（本人確認・連絡先登録など明示的な要求か）を確認してから許可する。心当たりがなければ拒否してよい。
  • Claude Code changelog (v2.1.317)
