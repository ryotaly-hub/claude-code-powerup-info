新機能

command/HTTP フックに `onFailure: "block"` が追加、起動失敗・タイムアウト時にアクションを止められるように（v2.1.295）

従来、command フックや HTTP フックが起動に失敗したりタイムアウトしたりすると、そのフックは素通りになり、本来チェックするはずだったツール呼び出し等のアクションがそのまま実行されてしまっていた。

v2.1.295 では、フック設定に onFailure: "block" を指定できるようになった。これを付けたフックは、起動できない・タイムアウトする・想定外の終了コードを返す、のいずれの場合もアクションをブロックする側に倒れる。

つまりこう使う

  • 危険なコマンドのブロックなどセキュリティ目的で使っている command/HTTP フックの設定に "onFailure": "block" を追加する
  • これにより、フック側の不調（ネットワーク断やタイムアウト）が原因でガードが無効化される事故を防げる
  • Claude Code Changelog — v2.1.295
注意点

自然言語で書いた `prompt`/`agent` フックが、ブロックすべき操作を素通りさせていた不具合が修正（v2.1.294）

「Block commands that...」のような自然言語の指示文で書いた prompt フック・agent フックが、本来止めるべき操作を通してしまうケースがあった。v2.1.294 でこの抜け穴が修正された。

合わせて、Stop / SubagentStop に付けた「Carry on if the build is broken」のような指示文フックの判定も改善され、Claude が意図せず早期に止まりにくくなった。

つまりこう使う

  • 自然言語の指示文でセキュリティ目的の hook を書いている場合は、v2.1.294 以降に更新してから想定どおりブロックされるか再確認する
  • Claude Code Changelog — v2.1.294
エコシステム

tool search 経由でモデルが読む MCP ツール説明の切り捨てが 2,048 文字から 16,384 文字に拡大（v2.1.295）

tool search を使って遅延読み込みされる MCP ツールの説明文は、従来 2,048 文字で切り捨てられていた。v2.1.295 でこの上限が 16,384 文字に拡大され、長めの説明を書いている MCP サーバーでも途中で切れにくくなった。

つまりこう使う

  • 自作・導入済みの MCP サーバーで説明文が長くツール説明が途中で切れていた場合、更新後に改めて挙動を確認する（起動時から常時読み込まれるサーバーには影響しない）
  • Claude Code Changelog — v2.1.295
注意点

サブエージェントが `skills` フィールドから一度にプリロードするスキルが最大32件に制限（v2.1.295）

サブエージェント定義の skills フィールドに33件以上のスキルを指定していても、v2.1.295 以降はプリロードされるのは最大32件・各1回のみになる。Skill ツールを持つサブエージェントであれば、プリロードされなかった残りのスキルも自分で呼び出すことは可能。

つまりこう使う

  • 多数のスキルを割り当てているサブエージェント定義があれば、重要なスキルが32件の枠に収まっているか確認する
  • 収まらない場合は、そのサブエージェントに Skill ツールを持たせて必要時に明示的に呼び出す設計にする
  • Claude Code Changelog — v2.1.295
Tips

Grep ツールへの `-l` / `-c` / `-r` フラグ付き検索が失敗せず実行されるように（v2.1.295）

従来、Grep ツールの呼び出しに grep の -l（ファイル名のみ表示）・-c（件数表示）・-r（再帰）といったフラグを含めると、呼び出し自体が失敗していた。v2.1.295 でこれらのフラグを含む呼び出しも正しく実行されるようになった。

つまりこう使う

  • Claude に grep -rl パターン のような grep 由来のフラグ付き検索を指示しても、以前のような失敗は起きなくなった
  • Claude Code Changelog — v2.1.295
