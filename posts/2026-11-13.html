新機能

MCPサーバーのツール呼び出しが「タスク」として自動でバックグラウンド実行に

MCPサーバーが対応していれば、ツール呼び出しをタスクとして実行した時点でClaude Codeがすぐバックグラウンドに回し、完了したらClaudeに結果を知らせるようになった。これまでは呼び出し中ターミナルがブロックされていたケースがある。

待ちたくない場合は環境変数CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUNDで、ツール呼び出し内で完了を待つ従来の動作に戻せる。

つまりこう使う

  • 時間がかかるMCPツール（検索・ビルド・外部API呼び出しなど）を使うなら、特に何もしなくてもターミナルが固まらなくなる
  • 完了を待って逐次処理させたい場合だけCLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1を設定する
  • Claude Code changelog (v2.1.319)
新機能

`permissions.denyInsteadOfPrompting`で許可待ちの代わりに拒否して続行できる

この設定を有効にすると、本来なら許可プロンプトで止まるはずのツール呼び出しが、待たずにその場で拒否されてターンが継続する。ターミナルセッションだけでなくサブエージェントやチームメイトにも適用される。CIやヘッドレス実行で誰も確認に答えられず止まってしまうケースの回避に向いている。

つまりこう使う

  • settings.jsonに"permissions": { "denyInsteadOfPrompting": true }を追加する
  • -pでの自動実行やサブエージェントが多いワークフローで、確認待ちのまま止まるのを避けたいときに設定する
  • Claude Code changelog (v2.1.319)
Tips

`/tasks`の「Earlier in this session」から終了済みサブエージェントに後から話しかけられる

/tasksに「Earlier in this session」という行が増え、一覧からすでに外れた完了済みサブエージェントや、セッションを再起動した後のサブエージェントも再び開いてメッセージを送れるようになった。終わったはずのサブタスクに後から追加の指示を出したいときに使える。

つまりこう使う

  • /tasksを開き「Earlier in this session」から目的のサブエージェントを選んで再度メッセージを送る
  • 「さっき終わったあのサブエージェントに追加確認したい」というときに、新規に作り直さず続きから聞ける
  • Claude Code changelog (v2.1.319)
注意点

セルフペースの`/loop`がデフォルトで「ターン終了＝停止」に変更

間隔を省略して自動ペースさせる/loopは、これまでターンが終わるたびに次回の起動を自動でスケジュールし続けていたが、v2.1.319以降はターンが何もスケジュールせずに終わると、そこでループが止まる仕様になった。従来通り動かし続けたい場合は環境変数CLAUDE_CODE_LOOP_KEEPALIVE=1を設定する必要がある。

つまりこう使う

  • 既存のセルフペース/loopを長時間動かしっぱなしにしている場合は、途中で止まっていないか確認する
  • 止めたくない常駐ループにはCLAUDE_CODE_LOOP_KEEPALIVE=1を設定してから起動する
  • Claude Code changelog (v2.1.319)
注意点

MonitorでwatchしているBashコマンドにも、通常の許可ルールが適用されるように

Monitorツールでバックグラウンド実行中のWebSocketなどをwatchしている場合、そこから発行されるBashコマンドにも通常のルールが適用されるようになった。denyルールに一致すれば拒否され、askルールが付いていればMonitor経由・bypassモード・auto modeであっても確認プロンプトがスキップされなくなった。

つまりこう使う

  • Monitorでログを継続監視させるワークフローを組んでいる場合、watch対象から実行されるBashコマンドが想定通り許可・拒否されるか確認する
  • bypass/auto modeだからといってMonitor経由のBashコマンドが無条件に通るとは考えない
  • Claude Code changelog (v2.1.319)
