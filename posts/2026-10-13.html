エコシステム

MCP ツール説明・サーバー指示文の既定の文字数上限が2,048文字から4,096文字に拡大（v2.1.296）

Claude Code が起動時にプロンプトへそのまま載せる MCP ツールの説明文や、MCP サーバーの指示文（instructions）には文字数上限があり、これまでは既定で2,048文字で切り捨てられていた。v2.1.296 からこの既定値が4,096文字に拡大された。

これは tool search 経由でモデルが読む説明文の上限（v2.1.295 で2,048文字から16,384文字に拡大済み）とは別の設定で、起動時に最初からプロンプトに載る分の上限にあたる。

つまりこう使う

  • 自作 MCP サーバーのツール説明文やサーバー指示文が2,048文字制限を想定して短く削っていた場合、4,096文字まで書けるようになったので説明を見直す余地がある
  • isDeferred: false（v2.1.293〜）でツールを最初からプロンプトに載せている場合は、こちらの上限が効く点に注意する
  • Claude Code Changelog
注意点

Bash 権限チェックが `BASH_ARGV0` を使ったコマンドを自動承認していた不具合を修正、確認が入るように（v2.1.296）

シェル変数 BASH_ARGV0 を代入してから使うタイプの Bash コマンドは、実質的に別のコマンド名で実行しているのと同じ効果を持つことがあるが、これまでの権限チェックはこれを見抜けずに自動承認していた。v2.1.296 でこの不具合が修正され、このパターンのコマンドには確認プロンプトが入るようになった。

つまりこう使う

  • allow ルールで特定コマンドだけを自動承認する運用をしている場合、BASH_ARGV0 を使った迂回が今後は確認を求められることを前提にしておく（既存の allow ルール自体への影響はない）
  • Claude Code Changelog
Tips

Bash の for ループで glob パターンを展開するコマンドの権限判定精度が改善（v2.1.295）

for f in *.txt; do ...; done のように glob パターンを for ループで展開する Bash コマンドは、これまで権限チェックが対象ファイルを正しく認識できず、判定が不正確になることがあった。v2.1.295 でこの判定精度が改善された。

つまりこう使う

  • 複数ファイルをまとめて処理する for ループを許可ルールやサンドボックス自動許可に頼っている場合、以前より判定が正確になっている点を前提に、必要なら許可ルールを見直す
  • Claude Code Changelog
注意点

`claude -p` 実行で、応答のストリーミング完了前に Skill tool が終わるとスキルの `allowed-tools`/`effort` が失われ、Bash コマンドが拒否される不具合を修正（v2.1.295）

claude -p（ヘッドレス実行）でスキルを呼び出した際、Skill tool の処理が応答のストリーミング完了より先に終わると、そのスキルに設定した allowed-tools や effort が反映されず、スキル内の Bash コマンドが権限拒否されることがあった。v2.1.295 でこの不具合が修正された。

つまりこう使う

  • CI などで claude -p からスキルを呼び、スキル内の Bash コマンドが原因不明で拒否されていた場合は、この不具合が原因だった可能性がある。更新後に同じスキルを再実行して解消を確認する
  • Claude Code Changelog
ワークフロー

ヘッドレス・SDK セッションで、15秒以上切れたリモート MCP サーバーへの再接続が改善、過度な再試行に自動でバックオフ（v2.1.295）

ヘッドレスセッションや Agent SDK セッションでは、リモート MCP サーバーが15秒を超えて切断されるとそのまま再接続されずに切れたままになったり、逆に接続直後に切断するサーバーに対してタイトループで再接続を繰り返したりする不具合があった。v2.1.295 でこれが修正され、繰り返し切断されるサーバーへの再接続は最大30秒まで自動的にバックオフするようになった。

つまりこう使う

  • SDK や -p でリモート MCP サーバーを使う構成で、一時的な切断後にツールが使えなくなる事象が起きていた場合、更新後は自動で再接続されるようになっているはずか確認する
  • Claude Code Changelog
Tips

Windows: hooks が `CLAUDE_ENV_FILE` に書き込んだ環境変数が PowerShell から見えない不具合を修正（v2.1.296）

hooks が CLAUDE_ENV_FILE に単純な代入文だけを書き込んだ場合、Windows の PowerShell ツールからその環境変数が見えないことがあった。v2.1.296 でこの不具合が修正され、PowerShell でも hooks が設定した環境変数を参照できるようになった。

つまりこう使う

  • Windows で SessionStart などの hooks から CLAUDE_ENV_FILE 経由で環境変数をセットし、以降の PowerShell コマンドで使う運用をしている場合、更新後に正しく読めているか確認する
  • Claude Code Changelog
