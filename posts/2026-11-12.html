POWERUP INFO / VOL.54

直近の号はv2.1.319以降を中心に扱ってきたが、その直前のv2.1.311〜318（10/26〜11/4）にも手を動かせる変更がいくつかあった。Opus 4.8のfast mode廃止期限、新しい権限設定、バックグラウンドサブエージェントの挙動変更、ultrathinkのエフォート強化の4点をまとめる。

この号の内容

  1. Opus 4.8のfast modeは2026年11月30日に廃止。Opus 5.5への移行が必要
  2. `permissions.blockWritesOutsideWorkingDirectories`で、作業ディレクトリ外への書き込みをどの権限モードでも拒否できる
  3. バックグラウンドサブエージェントのシェルコマンドは、3分経つと自動でバックグラウンド化される
  4. `ultrathink`がOpus 5.5・Sonnet 5.5・Haiku 5.5・Fable 5.1でxhighエフォート実行に
  5. Webやシェルのツール呼び出しがアカウントのメールアドレスをネットワークに送る前に、確認が入るように
注意点

Opus 4.8のfast modeは2026年11月30日に廃止。Opus 5.5への移行が必要

v2.1.316で、Opus 4.8のfast modeが2026年10月30日付で非推奨になった。2026年11月30日に完全に削除され、削除後はOpus 4.8へのfast modeリクエストがエラーを返すようになる（標準速度へのフォールバックはしない）。fast modeの高速さを維持したい場合はOpus 5.5へ移行する必要がある。

つまりこう使う

  • /modelでOpus 4.8のfast modeを使っている場合は、11月30日より前にOpus 5.5に切り替えておく。
  • CI・自動化スクリプトでモデルをハードコードしている場合は、Opus 4.8 fast mode指定を洗い出して更新する。

新機能

`permissions.blockWritesOutsideWorkingDirectories`で、作業ディレクトリ外への書き込みをどの権限モードでも拒否できる

v2.1.314で追加された設定。有効にすると、Write・Edit・NotebookEditが作業ディレクトリ（複数指定している場合はそのいずれか）の外のパスへの書き込みを、auto modeやbypassモードを含むすべての権限モードで拒否するようになる。意図しないディレクトリへの書き込みを構造的に防げる。

つまりこう使う

  • 設定ファイルに"permissions": { "blockWritesOutsideWorkingDirectories": true }を追加すると、作業ディレクトリ外への書き込みが常にブロックされる。
  • 複数リポジトリを横断して作業させたいセッションでは、意図せず他ディレクトリへの書き込みが止まる点に注意。
  • Claude Code Changelog
ワークフロー

バックグラウンドサブエージェントのシェルコマンドは、3分経つと自動でバックグラウンド化される

v2.1.318の変更。バックグラウンドで動くサブエージェントが実行するシェルコマンドは、プロバイダーを問わず3分経過すると自動的にバックグラウンド実行に切り替わるようになった。長時間のビルドやテストを待っている間にプロンプトキャッシュが切れてコストが増えるのを防ぐための挙動。

つまりこう使う

  • サブエージェントに長時間コマンドを投げるワークフローでは、3分を境にコマンドの扱いが変わる前提で結果の受け取り方（ポーリングや通知）を考えておく。
  • Claude Code Changelog
Tips

`ultrathink`がOpus 5.5・Sonnet 5.5・Haiku 5.5・Fable 5.1でxhighエフォート実行に

v2.1.311で、インタラクティブターミナルでのultrathinkが、Anthropic API経由のOpus 5.5・Sonnet 5.5・Haiku 5.5・Fable 5.1においてそのターンをxhighエフォートで実行するようになった。Claudeが作業中にタイプすると、そのターンの残りのエフォートも引き上げられる。

つまりこう使う

  • 対応モデルで難しいタスクに当たったら、プロンプトにultrathinkと書くだけでそのターンをxhighエフォートに引き上げられる。
  • 作業中に効果を感じない場合は、Claudeがまだ動いている間にultrathinkと打ち込んで残りのターンのエフォートを上げる、という使い方もできる。
  • Claude Code Changelog
注意点

Webやシェルのツール呼び出しがアカウントのメールアドレスをネットワークに送る前に、確認が入るように

v2.1.317の変更。WebFetchやBashなどのツール呼び出しが、ユーザーのアカウントのメールアドレスを外部ネットワークに送信しようとする場合に、事前に確認を求めるチェックが追加された。個人情報が意図せず外部サービスに渡るのを防ぐための安全対策。

つまりこう使う

  • 自動化スクリプトやhookでメールアドレスを扱っている場合、auto modeやbypassモードでもこの確認がどう扱われるかを一度確かめておくとよい。
  • Claude Code Changelog
