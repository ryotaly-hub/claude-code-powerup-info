POWERUP INFO / VOL.70
2026.11.28

今号はv2.1.328〜332の中で、これまでの号で拾っていなかった項目をまとめた。確認ダイアログの誤操作対策から、computer useやplan modeの挙動変更、フィードバック・バグ報告系の地味な改善まで、実務に効く変更を選んだ。

この号の内容

  1. VS Code・DesktopのCode tabに、会話の一部が保存できなかった場合の警告が追加
  2. `/feedback`のドラフトが「Not now」で開くようになり、レポート単体か文字起こし付きかを選べるように
  3. `/bug`はYes/No確認を挟んでから送信するように変更。連打での誤送信を防止
  4. 確認ダイアログでPgUp/HomeがNo側に移動するように変更
  5. computer use(macOS)の安全ルールが更新され、一部操作が拒否されたり入力が遅くなることがある
  6. Desktop・VS Codeのplan modeで、判断できないコマンドが拒否でなく承認待ちに変わった
Tips

VS Code・DesktopのCode tabに、会話の一部が保存できなかった場合の警告が追加

VS Code拡張とDesktopアプリのCode tabで、セッションの一部が保存できなかったときに、/compactで保存する方法を案内する警告が表示されるようになった。合わせて、再開したセッションで以前のメッセージが読み込まれていない場合も、ターミナル同様に通知が出るようになった。

つまりこう使う

  • この警告が出たら、放置せずに/compactを実行して会話を保存し直す
  • Claude Code Changelog
Tips

`/feedback`のドラフトが「Not now」で開くようになり、レポート単体か文字起こし付きかを選べるように

ターミナルで/feedbackを使うと、ドラフトが「Not now」の状態で開くようになった。その上に、レポートだけを送るか、会話の文字起こしも付けて送るかを選べる行が別に用意されている。

つまりこう使う

  • 機密情報を含む会話では、文字起こし付きではなくレポート単体の行を選んで送信する
  • Claude Code Changelog
注意点

`/bug`はYes/No確認を挟んでから送信するように変更。連打での誤送信を防止

/bugでバグレポートを作成したあと、以前はEnterを連打すると確認なしに送信されてしまうことがあった。今はYes/Noで確認が入るようになり、意図せず送信してしまうことがなくなった。

つまりこう使う

  • /bug実行後は、送信前のYes/No確認を必ず確認してから進める
  • Claude Code Changelog
注意点

確認ダイアログでPgUp/HomeがNo側に移動するように変更

/clearをagent viewから実行する場合など、破壊的な操作を確認するダイアログで、PgUpキーとHomeキーを押すとカーソルがNoに移動するようになった。従来のキー操作の感覚で押すと、意図と違う選択をしてしまう可能性がある。

つまりこう使う

  • 確認ダイアログでは矢印キーか明示的なクリックで選択し、PgUp/Homeでの誤操作に注意する
  • Claude Code Changelog
注意点

computer use(macOS)の安全ルールが更新され、一部操作が拒否されたり入力が遅くなることがある

macOSのcomputer useが新しい安全ルールに切り替わった。この影響で、以前は通っていた一部の操作が拒否されるようになったり、文字入力の速度が遅くなる場合がある。

つまりこう使う

  • computer useで以前動いていた操作が急に拒否されるようになったら、安全ルール更新が原因の可能性を考慮する
  • Claude Code Changelog
ワークフロー

Desktop・VS Codeのplan modeで、判断できないコマンドが拒否でなく承認待ちに変わった

Desktopアプリ内のCode tabとVS Code拡張で、ManualまたはAccept editsのモードからplan modeに入ったとき、auto modeの安全チェックが判断できないコマンドは、これまでは拒否されていたが、今は承認を求める扱いになった。

つまりこう使う

  • DesktopのCode tabやVS Codeでplan modeを使っているとき、判断不能なコマンドで止まったら拒否ではなく承認待ちだと理解して対応する
  • Claude Code Changelog
