v2.1.311 の changelog から6本選んだ。CLAUDE.md や大規模な一括編集にまつわる地味だが刺さる不具合修正に加え、`ultrathink` の効き方の変更、サブエージェントの MCP 接続待ち問題、Slack 連携の投稿ルール確認まで、日々の使い方に直結する変更をまとめた。

この号の内容

  1. CLAUDE.md に非常に長いリスト項目があると、起動時やファイルの読み書き時に長時間フリーズする不具合を修正
  2. 数千行規模の一括編集で Write/Edit が最大5秒遅延し、「0 lines changed」と誤表示する不具合を修正
  3. サブエージェント起動後に接続が完了した MCP サーバーのツールを、そのサブエージェントが使えなかった不具合を修正
  4. `ultrathink` が対象モデルでそのターンだけ xhigh エフォートで動くように変更
  5. `SubagentStop` フックが、サブエージェント終了時に1回だけ実行されるべきところを、実行中のサブエージェントごとに約1分に2回呼ばれていた不具合を修正
  6. Slack 連携で、名前を指定していないチャンネルに投稿する前に、Claude がそのチャンネルのトピックを確認して投稿ルールをチェックするように変更
注意点

CLAUDE.md に非常に長いリスト項目があると、起動時やファイルの読み書き時に長時間フリーズする不具合を修正

v2.1.311 で、CLAUDE.md（および MEMORY.md など）の中に極端に長い1つのリスト項目があると、Claude Code の起動時や、ファイルを読み書きするたびに処理が長時間止まってしまう不具合が修正された。長い説明や手順を1項目にまとめて書いているプロジェクトほど影響を受けやすかった。

つまりこう使う

  • CLAUDE.md の箇条書きが1項目でやたら長くなっている場合は、v2.1.311 以降に更新したうえで、見出しや空行で複数項目に分けておくと今後も読みやすく安全になる。
  • claude-code v2.1.311 release notes
注意点

数千行規模の一括編集で Write/Edit が最大5秒遅延し、「0 lines changed」と誤表示する不具合を修正

v2.1.311 で、ファイルの数千行を一度に書き換えるような大きな Write/Edit を実行した際、実行完了後に最大5秒ほど処理が止まり、さらに結果が「0 lines changed」と誤表示されていた不具合が修正された。実際には編集は正しく反映されていたが、表示だけを見て失敗したと誤解しやすい状態だった。

つまりこう使う

  • 大規模な自動リファクタリングやコード生成で Write/Edit の結果表示が怪しいと感じたら、v2.1.311 以降かを確認する。古いバージョンのままなら「0 lines changed」表示だけで判断せず、実ファイルの差分を見て確認する。
  • claude-code v2.1.311 release notes
ワークフロー

サブエージェント起動後に接続が完了した MCP サーバーのツールを、そのサブエージェントが使えなかった不具合を修正

v2.1.311 で、サブエージェントの起動タイミングよりあとに接続が完了する MCP サーバーがある場合、そのサーバーのツールをサブエージェントが認識できず使えなかった不具合が修正された。起動が遅い MCP サーバーを使っている構成で、親セッションでは使えるツールがサブエージェント側では見えない、という状況が起きていた。

つまりこう使う

  • 接続に時間がかかる MCP サーバーをサブエージェントに使わせたい場合、v2.1.311 以降なら起動直後に接続中でも最終的にツールが使えるようになる。以前のバージョンで「サブエージェントだけツールが見えない」と感じていた人は更新して再確認する。
  • claude-code v2.1.311 release notes
ワークフロー

`ultrathink` が対象モデルでそのターンだけ xhigh エフォートで動くように変更

v2.1.311 で、対話型ターミナルで ultrathink と打つと、Opus 5.5・Sonnet 5.5・Haiku 5.5・Fable 5.1（Anthropic API 経由）では、そのターンだけエフォートレベルが xhigh に上がるようになった。Claude が作業中に打った場合は、残りのターンのエフォートが上がる。ただし引用符の中やファイルパスの一部として書かれた ultrathink は対象にならないよう変更されている。

つまりこう使う

  • 普段は通常のエフォートで作業し、特にじっくり考えさせたい一手だけ ultrathink と打つ。/effort でレベルを都度切り替える手間が減る。対象モデル・提供元（Anthropic API 経由）であることだけ確認しておく。
  • claude-code v2.1.311 release notes
注意点

`SubagentStop` フックが、サブエージェント終了時に1回だけ実行されるべきところを、実行中のサブエージェントごとに約1分に2回呼ばれていた不具合を修正

v2.1.311 で、SubagentStop フックが本来の「サブエージェントが終了したタイミングで1回」ではなく、実行中のサブエージェントが存在する間、1体につき約1分に2回のペースで呼ばれ続けていた不具合が修正された。通知やログ記録をこのフックに書いている場合、これまで意図しない回数実行されていた可能性がある。

つまりこう使う

  • SubagentStop フックで通知やログ記録をしている場合、重複実行を前提に回数チェックなどのワークアラウンドを入れていたら、v2.1.311 への更新後は外してよい。
  • claude-code v2.1.311 release notes
エコシステム

Slack 連携で、名前を指定していないチャンネルに投稿する前に、Claude がそのチャンネルのトピックを確認して投稿ルールをチェックするように変更

v2.1.311 で、Slack 連携から Claude がメッセージを送る際、ユーザーが明示的に名前を挙げていないチャンネルに投稿しようとすると、まずそのチャンネルのトピック・説明を確認し、「そこへの投稿は望ましくない」と書かれていればユーザーに伝えるようになった。意図せず無関係なチャンネルに投稿してしまう事故を減らす狙いの変更。

つまりこう使う

  • Slack MCP 経由で Claude に投稿させる運用をしている場合、投稿先チャンネルのトピックに投稿ルール（例:「お知らせはここに書かない」等）を書いておくと、Claude がそれを踏まえて投稿先を判断するようになる。
