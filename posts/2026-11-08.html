前号でまだ扱っていなかったv2.1.319の項目を5本。CIで`claude -p`を使っている人向けの終了コード修正、セキュリティ関連の2件、日々のコマンド実行で地味に効く修正をまとめた。

この号の内容

  1. `claude -p`がauto modeでアクションを拒否されたときも終了コード0を返していた不具合を修正、CI連携は要確認
  2. Bashの権限チェックを回避できる不具合と、worktree作成時のサンドボックス脱出を修正。更新を推奨
  3. `timeout 30 rg foo`のように読み取り専用コマンドをtimeoutで囲むと出ていた不要な許可確認が解消
  4. `/branch`より前のチェックポイントへの`/rewind`が「No files were restored」で失敗する不具合を修正
  5. 行頭に空白・タブ・改行が入ったスラッシュコマンドが、実行されず平文としてClaudeに送られてしまう不具合を修正
注意点

`claude -p`がauto modeでアクションを拒否されたときも終了コード0を返していた不具合を修正、CI連携は要確認

auto mode有効時、安全性チェックが利用できないためにアクションが拒否された場合でも、claude -pはこれまでテキスト出力・JSON出力ともに終了コード0（成功）を返していた。v2.1.319でこの不具合が修正され、この場合は終了コード1を返すようになった。

CIスクリプトなどでclaude -pの終了コードだけを見て成否判定している場合、これまでauto mode拒否のケースを「成功」として素通りしていた可能性がある。

つまりこう使う

  • CIやバッチ処理でclaude -pの終了コードを使って成否判定している場合、v2.1.319以降に更新したうえで、auto mode拒否時に正しく失敗として検知できるか確認する
  • これまで気づかずに見逃していた拒否ケースがないか、ログを遡って確認しておくとよい
  • Claude Code changelog (v2.1.319)
注意点

Bashの権限チェックを回避できる不具合と、worktree作成時のサンドボックス脱出を修正。更新を推奨

v2.1.319で2件のセキュリティ関連の不具合が修正された。1つは、環境変数のprefixを細工することでコマンドの一部を権限チェックから隠せてしまう不具合（Bash permission bypass）。もう1つは、worktree作成時にサンドボックスから脱出できてしまう不具合。いずれも実行環境の安全性に直接関わる修正。

つまりこう使う

  • --dangerously-skip-permissionsやBashサンドボックスを信頼して運用している場合は、早めにv2.1.319以降へ更新する
  • 特別な設定変更は不要。バージョンを上げること自体がそのまま対策になる
  • Claude Code changelog (v2.1.319)
Tips

`timeout 30 rg foo`のように読み取り専用コマンドをtimeoutで囲むと出ていた不要な許可確認が解消

読み取り専用のコマンド（rgやlsなど）をtimeout DURATIONで囲んで実行時間を制限していると、これまでは本来不要なはずの許可確認が出ていた。v2.1.319でこの不具合が修正され、プレーンなtimeoutで囲んだ読み取り専用コマンドは許可確認なしで実行されるようになった。

つまりこう使う

  • 検索コマンドなどにtimeout Nを付けて実行時間を制限する運用をしている場合、今後は許可確認が出ずにそのまま実行される
  • 逆に意図的に確認を出したい場合は、deny/askルール側で明示的に指定する必要がある
  • Claude Code changelog (v2.1.319)
Tips

`/branch`より前のチェックポイントへの`/rewind`が「No files were restored」で失敗する不具合を修正

/branchで会話を分岐させたあと、その分岐より前の時点のチェックポイントへ/rewindで戻そうとすると、「No files were restored」というエラーで失敗していた。v2.1.319でこの不具合が修正された。

つまりこう使う

  • /branchで分岐を作ってから分岐前の状態に戻したい場合、以前は失敗していたケースが解消されているので、/rewindをあらためて試してよい
  • Claude Code changelog (v2.1.319)
注意点

行頭に空白・タブ・改行が入ったスラッシュコマンドが、実行されず平文としてClaudeに送られてしまう不具合を修正

スラッシュコマンドの前に空白・タブ・改行が入っていると、これまではコマンドとして実行されず、そのままの文字列がClaudeへ平文メッセージとして送られてしまっていた。コピー＆ペーストなどで先頭に余分な空白が入り、意図したスラッシュコマンドが動かなかったケースはこれが原因だった可能性がある。v2.1.319で修正済み。

つまりこう使う

  • 以前スラッシュコマンドが動かなかった経験がある場合、先頭の余分な空白が原因だった可能性がある。更新後は同じ入力でも正しく実行されるか確認してみるとよい
  • Claude Code changelog (v2.1.319)
