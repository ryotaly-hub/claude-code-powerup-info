新機能

ターミナルが Claude Code の作業状態を表示できる OSC 7501（Program Status Protocol）に対応（v2.1.295）

Claude Code が OSC 7501（Program Status Protocol） に対応した。これはターミナル側に「作業中」「入力待ち」「完了」といった状態をエスケープシーケンスで知らせる仕組みで、対応するターミナルエミュレータや tmux のステータスバーなら、どのペイン・タブが入力待ちで止まっているかを色やアイコンで見分けられるようになる。

複数の Claude Code セッションを並行して走らせている場合、どれが応答を待っているかをいちいち画面を切り替えて確認する必要が減る。

つまりこう使う

  • 対応ターミナル（OSC 7501 を解釈できるもの）を使っていれば、特別な設定なしで自動的に状態表示が有効になる。
  • tmux などで複数ペインに Claude Code を並べて使っているなら、ステータスバー側の対応状況を確認しておくと「どのペインが止まっているか」が一目で分かるようになる。
  • Claude Code Changelog
注意点

managed `PreToolUse` hook の `"continue": false` による拒否が、ターン全体を終了させてしまっていた不具合を修正（v2.1.296）

組織管理（managed）の PreToolUse hook が "continue": false を返してツール呼び出しを拒否したとき、その1回の呼び出しだけでなく会話のターン全体が終了してしまう不具合があった。v2.1.296 で修正され、拒否された呼び出しだけが止まり、ターンはそのまま継続するようになった。

組織のガードレール用 hook を書いている場合、これまで「拒否したら会話も止まる」という前提で動いていた箇所があれば、挙動が変わる点に注意したい。

つまりこう使う

  • managed hook で危険な操作を "continue": false で拒否する設計をしている場合、v2.1.296 以降では拒否後も会話が続く前提で hook やその後の指示文を見直す。
  • Claude Code Changelog
ワークフロー

`claude -p` がターン終了後も居残るとき、何を待っているかを stderr に出すように（v2.1.295）

claude -p をスクリプトや CI から呼んだとき、最後のターンが終わったのにプロセスが終了せず「ハングしているように見える」ケースがあった。v2.1.295 では、そうした場合に何を待っているか（バックグラウンドのサブエージェントなど）を stderr に1行出すようになった。

つまりこう使う

  • CI や自動化スクリプトで claude -p を使っていて終了が遅い・止まって見えるときは、stderr を確認すれば原因が分かる。
  • ログを残す運用なら、stderr を標準出力と分けて記録しておくとデバッグが速くなる。
  • Claude Code Changelog
Tips

`CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS` で、無人実行時の 429/529 リトライ待機に上限を設定できるように（v2.1.295）

CI・-p・SDK などの無人（unattended）実行では、429（レート制限）や529（過負荷）エラーに対して自動でリトライ待機するが、これまで待機時間の上限を設定する手段がなかった。CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS を設定すると、その待機を一定時間で打ち切れるようになった。

つまりこう使う

  • CI パイプラインなど実行時間に上限があるジョブでは、CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS を設定して、過負荷リトライで想定外に長時間居残らないようにする。
  • Claude Code Changelog
エコシステム

Claude Tag（Claude in Slack）、ワークスペース/チャンネルの memory ファイルを Activity ページの Memory タブから編集できるように（v2.1.296）

Claude Tag Admin 権限を持つメンバーは、ワークスペースやチャンネルの memory ファイル（Claude がそのチャンネル・ワークスペースについて覚えている内容）を、Slack の会話内だけでなく Activity ページの Memory タブから直接作成・編集・削除できるようになった。

つまりこう使う

  • チャンネルごとの振る舞いを Slack 上のやり取りではなく管理画面でまとめて整理したいときに、Memory タブを使う。
  • 誤って記録された memory の削除も、該当チャンネルでの会話を探さずに Memory タブから直接行える。
  • Claude Code Changelog
Tips

VS Code 拡張、Claude が送ってきたファイルがクリック可能なファイル名付きの行で表示されるように（v2.1.295）

VS Code 拡張のチャットで Claude がファイルを送ってきたとき、専用の行としてファイル名が表示され、クリックするとそのまま開けるようになった。これまではテキストの中からパスを探して開く必要があった。

つまりこう使う

  • Claude が生成・送付したファイルを確認するときは、チャット内のファイル名をそのままクリックして開く。
  • Claude Code Changelog
