新機能

CLAUDE.md がないプロジェクトでは `AGENTS.md` を自動的に読むように（v2.1.277）

CLAUDE.md を置いていないプロジェクトで、代わりに AGENTS.md を読み込むようになった。AGENTS.md は Claude Code 以外のツールでも使われている共通形式のプロジェクト指示ファイルで、これまでは Claude Code 用に別途 CLAUDE.md を用意する必要があった。

読み込みの優先順位は instructionFiles 設定で切り替えられる。デフォルトの claude-md-or-agents-md は「CLAUDE.md があればそちらを優先、なければ AGENTS.md」という動作。両方を読ませたい場合は claude-md-and-agents-md に、AGENTS.md を無視して従来どおり CLAUDE.md だけにしたい場合は claude-md に変更できる。

なお CLAUDE.local.md も「CLAUDE.md がある」扱いになるため、個人用にこれだけ置いていると、チームの AGENTS.md が読まれなくなる点に注意。Amazon Bedrock・Google Vertex・Microsoft Foundry 経由ではまだ未対応。

つまりこう使う

  • 他ツール用に AGENTS.md をすでに書いているプロジェクトなら、CLAUDE.md を追加しなくてもそのまま Claude Code に読ませられる
  • CLAUDE.md と AGENTS.md を両方読ませたいなら /config の Project instructions（または settings.json の instructionFiles）を claude-md-and-agents-md に変更する
  • 個人用の CLAUDE.local.md を置いていてチームの AGENTS.md が無視されている場合は、この設定を疑う

注意点

Auto mode の安全確認、Claude API・Enterprise ではサーバー側の分類器がデフォルトに（v2.1.278）

Auto mode の安全確認（アクションを許可してよいかの分類器判定）が、Claude API アカウントと Enterprise プラン、および Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry・各種ゲートウェイ経由の利用で、サーバー側の分類器をデフォルトで使うようになった。サーバー側で実行される分類器のリクエストはモデル呼び出しに束ねられ、追加課金なしで処理される。

Bedrock・Vertex・Foundry・ゲートウェイ経由では CLAUDE_CODE_AUTO_MODE_SERVER=0 を設定すると、従来どおりの課金対象の分類器パスに戻せる。未対応のゲートウェイを挟んでいてサーバー側処理が失敗した場合は、課金対象パスへのフォールバック時に警告が表示されるようになった。あわせて /status に、このセッションの Auto mode 分類器がサーバー側で動いているかどうかを示す行が追加された。

つまりこう使う

  • Auto mode を Bedrock・Vertex・Foundry・自社ゲートウェイ経由で使っているなら、/status を開いて分類器がサーバー側で動いているか確認する
  • 独自ゲートウェイが未対応のフィールドを弾いて警告が出る場合は、CLAUDE_CODE_AUTO_MODE_SERVER=0 で従来の課金パスに切り替える
  • Claude Code Changelog（公式）
ワークフロー

`claude plugin eval` でプラグインをテストケース一式に対して採点できる

自作プラグインの効果を確認する claude plugin eval が追加された。テストケースのスイートに対してプラグインを実行して採点し、デフォルトでは同じスイートをプラグインなしでも流して比較する。両者のスコア差分（delta）を見れば、そのプラグインが実際にどれだけ効いているかが分かる。

プラグインのルートディレクトリで claude plugin eval init を実行すると、Claude が「良い結果とは何か」を聞いたうえでテストケースと採点基準（グレーダー）を提案し、一度スイートを試してファイルを書き出す。生成されたスイートは claude plugin eval . で実行でき、ターミナルにサマリー表、evals/results/report.html に実行ごとの詳細が出力される。評価の実行とグレーダーによる判定は実際のモデル呼び出しを伴うため、アカウントに課金される点は把握しておきたい。

つまりこう使う

  • 自作プラグインのルートで claude plugin eval init を実行し、Claude にテストケース案を出してもらう
  • スイートができたら claude plugin eval . を実行し、プラグインあり/なしのスコア差分を確認する
  • 実行結果の詳細は evals/results/report.html を開いて見る
  • Test plugins with evals（公式）

Tips

`maxEffortLevel` でプロバイダー問わずエフォートレベルの上限を設定できる

settings.json のトップレベル、または modelSettings 配下でモデルごとに maxEffortLevel を設定すると、Claude Code が使うモデルのエフォートレベルに上限をかけられる。ユーザーが /effort でそれより高いレベルを選んでも、設定した上限で頭打ちになる。Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry を含む、すべてのプロバイダーで有効。

つまりこう使う

  • コストを一定に抑えたいチームは共有の .claude/settings.json に "maxEffortLevel" を設定し、上限を明示する
  • モデルごとに上限を変えたい場合は modelSettings.<モデルID>.maxEffortLevel で個別に指定する（この値がグローバル設定より優先される）
  • Settings reference: maxEffortLevel（公式）

Tips

VS Code 拡張、プロンプトボックスのエージェント数をクリックしてサブエージェントの様子を確認できる

VS Code 拡張のプロンプトボックス下部に表示されるエージェント数をクリックすると「エージェントマップ」が開き、実行中のサブエージェントを一覧できる。各サブエージェントの読み取り専用トランスクリプトをその場で開いたり、不要なものを停止したりできる。

あわせて、コマンドメニューの Customize セクションから「Hooks」または「Permissions」を選ぶと、ユーザー・プロジェクト・ローカルの各設定にフックや権限ルールを GUI から追加・削除できるようになった。

つまりこう使う

  • VS Code でサブエージェントを並行して走らせているときは、プロンプトボックス下部のエージェント数をクリックして状況を確認する
  • 手が離せないサブエージェントは、エージェントマップからその場で停止する
  • フックや権限ルールを手で JSON に書く代わりに、コマンドメニューの Customize > Hooks / Permissions から編集する
