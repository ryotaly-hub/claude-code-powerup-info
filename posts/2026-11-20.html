POWERUP INFO / VOL.62
2026.11.20

11月19日リリースのv2.1.328・v2.1.329から、`/code-review`とauto modeの既定動作に関わる変更を中心に選んだ。どちらも「これまでの挙動を知らずに使うと驚く」種類の変更なので、CIスクリプトや無人実行の運用をしている場合は特に確認しておきたい。

この号の内容

  1. `/tasks`に、セッションのスケジュールタスク・`/loop`のウェイクアップ・ゴール・フォークが一覧表示されるように
  2. `/code-review`は既定でバグとCLAUDE.md違反のみを報告し、ターゲット未指定だとブランチ全体をレビューするように
  3. 権限モードを指定していないインタラクティブセッションが、既定でautoモードで起動するように
  4. `max_tokens`到達時の自動リトライが廃止。サードパーティゲートウェイ向けに`CLAUDE_CODE_MAX_OUTPUT_TOKENS`が登場
  5. Code Mode内のスクリプトは、PreToolUseフックがエラーを返しても既定では止まらなくなった
  6. auto modeが`git status`の実行回数を減らし、大きいリポジトリでの待ち時間が短縮
新機能

`/tasks`に、セッションのスケジュールタスク・`/loop`のウェイクアップ・ゴール・フォークが一覧表示されるように

v2.1.329で、/tasksにそのセッションのスケジュールタスク、/loopのウェイクアップ、ゴール、この会話からのフォークが表示されるようになった。これまでは種類ごとに別々のコマンドで確認する必要があったものが、1つの一覧でまとまって見られる。

つまりこう使う

  • バックグラウンドのフォークや/loop、スケジュールタスクを同時に走らせている場合は、/tasksを実行すると今動いているものを一覧で確認できる。
  • 不要になったタスクは一覧からxで停止できる（確認が入る）。
  • Claude Code Changelog (v2.1.329)
ワークフロー

`/code-review`は既定でバグとCLAUDE.md違反のみを報告し、ターゲット未指定だとブランチ全体をレビューするように

v2.1.328で、/code-reviewはほとんどのモデルでバグとCLAUDE.md違反のみを報告するようになった。再利用・簡略化・効率化といった指摘は対象から外れたので、そちらが欲しい場合は/simplifyを使う。各所見はImportant・Pre-existing・Nitのいずれかに分類され、末尾に修正案がつくようになり、問題がなければ一覧は「Code review found no issues.」と表示される。さらにv2.1.329で、ターゲットを指定せずに実行した場合はほとんどのモデルで直前の差分だけでなくブランチ全体をデフォルトブランチと比較してレビューするようになり、複数コミットのブランチで差分を見失う不具合も修正された。

つまりこう使う

  • バグやCLAUDE.md違反を知りたいときは/code-review、重複・簡略化・効率化などの整理を見たいときは/simplifyと使い分ける。
  • ターゲットを指定せずに/code-reviewを実行すると今はブランチ全体を見るので、直前の差分だけ見たいときはレビュー対象（コミットやブランチ名など）を明示的に渡す。
  • Claude Code Changelog (v2.1.328)
  • Claude Code Changelog (v2.1.329)
注意点

権限モードを指定していないインタラクティブセッションが、既定でautoモードで起動するように

v2.1.328で、auto modeがClaude Opus 4.6・Sonnet 4.6でAmazon Bedrock・Google CloudのAgent Platform・Microsoft Foundry・Claude apps gatewayでも使えるようになった。これに合わせて、起動時に権限モードを明示的に指定していないインタラクティブセッションは、既定でauto modeで起動するようになった。これまで確認プロンプトが都度出る前提で運用していた場合、挙動が変わる。

つまりこう使う

  • 従来どおり確認プロンプトを都度出したい場合は、起動時に--permission-mode defaultなどで権限モードを明示的に指定する。
  • 今のセッションがどの権限モードで動いているかは/statusで確認できる。
  • Claude Code Changelog (v2.1.328)
注意点

`max_tokens`到達時の自動リトライが廃止。サードパーティゲートウェイ向けに`CLAUDE_CODE_MAX_OUTPUT_TOKENS`が登場

v2.1.329で、v2.1.326から入っていた「max_tokensエラーの上限に達したときに自動でリトライする」挙動が削除された。サードパーティのゲートウェイ経由でモデルが受け付ける出力トークン数がClaude Code側の既定より少ない場合は、環境変数CLAUDE_CODE_MAX_OUTPUT_TOKENSにその上限値を設定して対応する。

つまりこう使う

  • サードパーティゲートウェイ経由でClaude Codeを使っていて、長い応答がmax_tokensエラーで止まるようになった場合は、CLAUDE_CODE_MAX_OUTPUT_TOKENS環境変数にゲートウェイ側モデルの出力上限トークン数を設定する。
  • Claude Code Changelog (v2.1.329)
Tips

Code Mode内のスクリプトは、PreToolUseフックがエラーを返しても既定では止まらなくなった

v2.1.329で、Code Mode内のスクリプトはPreToolUseフックがエラーを返しても、既定では拒否されずに実行が続くようになった（これまではフックのエラーでスクリプトが止まっていた）。拒否する挙動を保ちたい場合は、そのフックの設定に"onFailure": "block"を指定する。このonFailure: "block"オプションはv2.1.328でmcp_toolフックにも追加され、コマンド・HTTPフックと同じ指定ができるようになっている。

つまりこう使う

  • Code Modeでフックのエラーをスクリプト停止のトリガーとして使っている場合は、該当フックの設定に"onFailure": "block"を追加しないと、エラーが出ても処理が継続する点に注意する。
  • Claude Code Changelog (v2.1.328)
  • Claude Code Changelog (v2.1.329)
ワークフロー

auto modeが`git status`の実行回数を減らし、大きいリポジトリでの待ち時間が短縮

v2.1.329で、auto modeが安全確認のためにgit statusを実行する頻度が減り、大きいリポジトリでほとんどのリクエストの待ち時間が短くなった。一方で、変更を破棄するgitコマンドは、作業ツリーの状態を確認できるまでブロックされる場合がある。

つまりこう使う

  • 大きいリポジトリでauto modeのリクエストごとの待ち時間が気になっていた場合、この変更で改善されているはずなので特別な設定は不要。
  • git reset --hardなど変更を破棄するコマンドがauto modeで一時的にブロックされた場合は、作業ツリーに未保存の変更がないか確認してから再試行する。
  • Claude Code Changelog (v2.1.329)
