新機能

Code Modeが、Bedrock・Agent Platform・Foundry・AWS上のClaude Platformのターミナルセッションでも使えるように

v2.1.331で、Code Mode（スクリプトからツールを呼び出す実行モード）がターミナルセッションでも Amazon Bedrock・Google CloudのAgent Platform・Microsoft Foundry・AWS上のClaude Platform で使えるようになった。これまで対応環境が限られていたため、サードパーティ基盤でCode Modeの恩恵をそのまま受けられる範囲が広がった。

つまりこう使う

  • 社内でBedrock/Agent Platform/Foundryを使っている場合、ターミナルセッションからCode Modeを有効化してスクリプト経由のツール呼び出しに切り替えられる
  • Claude Code changelog
Tips

`claude doctor`に、APIへの接続状況を報告する新セクションが追加

claude doctorの出力に、APIへ到達できているかどうかをHTTPステータスやエラー内容と一緒に報告する「API connectivity」セクションが加わった。プロキシ経由の接続不良やネットワーク設定の問題を、まずここで切り分けられる。

つまりこう使う

  • APIに繋がらない・応答がないといった症状に遭遇したら、まずclaude doctorを実行してAPI connectivityの行を確認する
  • HTTPステータスが表示されれば、社内プロキシ側の問題かAnthropic側の問題かの当たりがつけやすい
  • Claude Code changelog
注意点

`CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION`で、モデル応答の圧縮を無効化できる

圧縮されたモデルの応答を途中で打ち切ってしまうプロキシの背後でClaude Codeを使っている場合、環境変数CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSIONを設定すると非圧縮のレスポンスを要求できるようになった。ストリーミングが不自然に途切れる・ハングするといった症状の切り分けに使える。

つまりこう使う

  • 社内プロキシ経由でストリーミング応答が途中で切れる場合、CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION=1を設定して症状が解消するか確認する
  • Claude Code changelog
ワークフロー

サブエージェントの確認ダイアログは選択肢がYes先頭の並びに変わったが、カーソルの初期位置は依然No

サブエージェントのビューで出る/ideの自動接続プロンプトや、/clear・/compact・/rewindの確認ダイアログは、選択肢の並び順が「Yes」が先頭に来るよう変更された。ただしデフォルトのカーソル位置は変わらず「No」のままなので、何も押さずにEnterを押せば引き続きNoが選ばれる。Yesを選ぶには明示的に上キーで移動する必要がある。

つまりこう使う

  • サブエージェントの確認ダイアログでは、迷わずそのままEnterを押せばNo側で確定できる（並びがYes先頭になった後も挙動は変わらない）
  • Yesを選びたいときだけ、上キーで一度移動してからEnterを押す
  • Claude Code changelog
エコシステム

VS Code拡張に「Fix with Claude Code」「Add to Chat」「Resolve Merge Conflicts」などが追加

VS Code拡張がv2.1.331で複数の統合を追加した。Source Controlビューの変更には「Add to Chat」で会話にそのまま渡せるボタンがつき、エディタのエラーに表示されるクイックフィックスから「Fix with Claude Code」を呼び出せるようになった。マージコンフリクトが出たファイルでは「Resolve Merge Conflicts」から解決を依頼でき、Notebookのセルも「Add Cell to Chat」で渡せる。

つまりこう使う

  • 差分レビュー中に気になる変更があれば、Source Controlの「Add to Chat」から直接質問・修正依頼する
  • エディタの赤波線エラーに出るクイックフィックス一覧から「Fix with Claude Code」を選ぶと、そのまま修正を依頼できる
  • マージコンフリクトが出たファイルでは、クイックフィックスの「Resolve Merge Conflicts」を試す
  • Claude Code changelog
注意点

11/30以降、managed設定のプラグインマーケットプレイスは既定で自動更新されるように

2026年11月30日以降、管理者側の設定（managed-settings.json）のextraKnownMarketplacesに登録したプラグインマーケットプレイスは、デフォルトで自動更新されるようになる。意図しないバージョンアップを避けたい場合は、該当エントリに"autoUpdate": falseを明示しておく必要がある。

つまりこう使う

  • 組織のmanaged-settings.jsonでextraKnownMarketplacesを使っている場合、11/30までに各エントリの自動更新を許容するか判断し、避けたいものには"autoUpdate": falseを追加しておく
  • Claude Code changelog
