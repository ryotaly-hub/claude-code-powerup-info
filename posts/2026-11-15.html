エコシステム

`plugin.json`の`engines["claude-code"]`で、プラグインの対応バージョンを宣言できるように

v2.1.323で、プラグインのplugin.jsonにengines["claude-code"]フィールドを追加できるようになった。対応するClaude Codeのバージョン範囲を書いておくと、範囲外のバージョンではそのプラグインがインストールされず、更新や読み込みも行われない。

claude plugin validateも、プラグインが提供するTypeScript製のhooksモジュールに対して型チェックを行うようになった。

つまりこう使う

  • 配布するプラグインのplugin.jsonにengines: { "claude-code": ">=2.1.323" }のような範囲を追加しておくと、古いバージョンのClaude Codeで動かずにユーザーが困る事故を防げる。
  • Claude Code Changelog
注意点

設定`subagentStatusLine`が削除された

v2.1.323で、サブエージェントの表示をカスタマイズするsubagentStatusLine設定が削除された。この設定をsettings.jsonやプラグインで指定していた場合、アップデート後は単に無視されるようになる。

つまりこう使う

  • settings.jsonや配布しているプラグインの設定にsubagentStatusLineが残っていないか確認し、残っていれば削除する。代替の表示手段は現時点でアナウンスされていない。
  • Claude Code Changelog
注意点

未知のモデルIDのコンテキストウィンドウ既定値が200Kから1Mに変更

v2.1.323で、Claude Codeが認識しないモデルIDを指定したときに想定するコンテキストウィンドウの既定値が、200Kトークンから1Mトークンに変わった。サードパーティのプロバイダー経由で未対応のモデルを使っている場合、この既定値をもとにコンテキスト使用量の見積もりが変わる。

つまりこう使う

  • 環境変数CLAUDE_CODE_DISABLE_1M_CONTEXT=1を設定すると、以前の200Kトークンの既定値に戻せる。カスタムモデルを使っていて挙動が変わったと感じたら、まずこれを試す。
  • Claude Code Changelog
ワークフロー

VS Code拡張で、実行中のBash・PowerShellコマンドの出力がチャットにライブ表示されるように

v2.1.323のVS Code拡張で、Claudeが実行しているBashやPowerShellのコマンドの出力が、完了を待たずにチャット上にリアルタイムで流れるようになった。長くかかるビルドやテストの進み具合を、チャット画面を離れずに確認できる。

つまりこう使う

  • VS Code拡張を最新版に更新するだけで有効になる。特別な設定は不要。
  • Claude Code Changelog
Tips

`claude -p`とSDKで、フックの実行が長引くと30秒ごとに進捗が表示されるように

v2.1.323で、claude -p（ヘッドレスモード）やAgent SDKを使ったセッションでhooksの実行が長くかかっている場合、30秒おきに進捗のハートビートが出力されるようになった。これまではhooksが重い処理をしていても、完了まで画面に何も出ず止まっているように見えた。

つまりこう使う

  • 重いpre-commit系のhookをスクリプトやCIからclaude -pで呼んでいる場合、ログに30秒おきの進捗が出るので、ハングしているのか処理中なのかの判断がしやすくなる。
  • Claude Code Changelog
Tips

`/claude-api latency-optimize`で、Claude APIコードのレイテンシの原因箇所を調べられる

v2.1.319で追加されたコマンド。自分のリポジトリにあるClaude API（Messages API）の呼び出しコードを対象に、どこがレスポンスを遅くしているかをClaude Code自身に調べてもらえる。

つまりこう使う

  • Claude APIを直接呼び出しているコードがあるリポジトリで/claude-api latency-optimizeを実行すると、キャッシュの使い方やストリーミングの有無など、待ち時間に関わる箇所を指摘してもらえる。
  • Claude Code Changelog
