v2.1.312 の changelog から6本選んだ。CLAUDE.md やルールファイルの事故りやすい上書き問題の修正に加え、hooks の同時実行数の明文化、クラウドセッション側の使い勝手の改善、Bedrock/Vertex 系でのシステムプロンプトの変更まで、構成を見直すきっかけになる変更をまとめた。

この号の内容

  1. 大きな CLAUDE.md・rules ファイル・`@` インクルードファイルを途中までしか読まずに上書きする不具合を修正
  2. prompt/agent hooks の同時実行数がセッションあたり最大24（サブエージェント含む）に制限。`timeout` の最小値は1秒
  3. クラウドセッションの Routine 作成・編集画面で、モデルピッカーからエフォートレベルを指定可能に
  4. フルスクリーン表示で、キュー済みメッセージの「to send now」をクリックすると待たずに送信できるように
  5. Bedrock・Vertex・Foundry・Mantle で、認識されないモデル名には短縮版のシステムプロンプトが使われるように変更
  6. GitHub の push イベントが遅れて届いた際、Code Review が古いコミットをレビューしてしまう不具合を修正
注意点

大きな CLAUDE.md・rules ファイル・`@` インクルードファイルを途中までしか読まずに上書きする不具合を修正

v2.1.312 で、CLAUDE.md や rules ファイル、@ で読み込んでいるファイルが非常に大きいと、Claude がファイルの一部しか読み込んでいない状態のまま Write で上書きしてしまう不具合が修正された。以後は Write がファイル全体を読んでから書き込むか、読み込みきれない場合は代わりに Edit を使うよう動作が変わっている。

つまりこう使う

  • CLAUDE.md やルールファイルが大きくなってきたプロジェクトでは、Write で丸ごと書き換えさせるのではなく、最初から Edit で差分だけ直させる運用にしておくと、v2.1.312 より前のバージョンでも事故を避けやすい。
  • v2.1.312 以降に更新したあとも、ファイルが巨大なままだと読み込みに時間がかかるので、肥大化した CLAUDE.md は見出しごとに分割しておくと安全。

ワークフロー

prompt/agent hooks の同時実行数がセッションあたり最大24（サブエージェント含む）に制限。`timeout` の最小値は1秒

v2.1.312 で、PreToolUse などの prompt/agent hooks が同時に実行できる数が、サブエージェントの分も含めて1セッションあたり最大24本までと明文化された。また hooks の timeout に指定できる最小値が1秒に決まった。多数のサブエージェントを並行起動しつつ各エージェントにフックを仕込む構成では、上限に当たると古いものから待たされる・切られる可能性がある。

つまりこう使う

  • parallel() やバックグラウンドサブエージェントを多数同時に動かすワークフローで hooks を使っている場合、1セッションで同時に走る hooks の総数が24を超えないか見積もっておく。
  • hooks の timeout を1秒未満に設定している箇所があれば、v2.1.312 以降は無効になるので1秒以上に直す。
  • claude-code v2.1.312 release notes
新機能

クラウドセッションの Routine 作成・編集画面で、モデルピッカーからエフォートレベルを指定可能に

v2.1.312 で、claude.ai/code の Routine（定期実行・GitHub イベント起動などのクラウドエージェント）を作成・編集する画面のモデルピッカーに、モデル選択とあわせてエフォートレベル（low/high/xhigh など）を指定する項目が追加された。あわせて環境設定のセットアップスクリプト欄にも、色分け・行番号・コピーボタン付きのエディタが付いた。

つまりこう使う

  • 毎朝の自動配信や定期レビューのような軽い Routine は低いエフォート、込み入った調査や大きなコード変更をさせる Routine は xhigh を選んでおくと、都度 /effort で切り替える手間が減る。
  • セットアップスクリプトを編集する際は、新しいエディタの行番号表示を使うとエラー箇所を特定しやすい。
  • claude-code v2.1.312 release notes
Tips

フルスクリーン表示で、キュー済みメッセージの「to send now」をクリックすると待たずに送信できるように

v2.1.312 で、フルスクリーンレンダリング中に次のメッセージとして入力待ちキューに積んだメッセージの下に出る「to send now」をクリックすると、現在の処理の完了を待たずにそのメッセージをすぐ送信できるようになった。

つまりこう使う

  • 作業中にキューへ複数の指示を積んだあと、途中で優先度の高い1件だけ先に処理させたくなったら、そのメッセージの下の「to send now」をクリックする。

注意点

Bedrock・Vertex・Foundry・Mantle で、認識されないモデル名には短縮版のシステムプロンプトが使われるように変更

v2.1.312 で、Amazon Bedrock・Google Cloud Vertex AI・Microsoft Foundry・Mantle 経由で、カスタムデプロイ名や推論プロファイル ARN など Claude Code が認識できないモデル名を指定している場合、通常より短いシステムプロンプトが使われるようになった。あわせて、安全性チェックでフラグが付いたメッセージの後に自動でモデルを切り替える動作も、未認識のモデル名に対して適用されるようになっている。

つまりこう使う

  • カスタムデプロイ名で運用していて以前と応答の雰囲気が変わったと感じたら、元の挙動に戻すには環境変数 CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 を設定する。
  • フラグ後の自動モデル切り替えが意図しないタイミングで起きて困る場合は CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 を設定して無効化する。
  • claude-code v2.1.312 release notes
ワークフロー

GitHub の push イベントが遅れて届いた際、Code Review が古いコミットをレビューしてしまう不具合を修正

v2.1.312 で、GitHub からの push イベントの通知が遅延して届いた場合に、Claude Code の Code Review 機能が最新コミットではなく古いコミットをレビューしてしまう、あるいはレビュー自体が行われない不具合が修正された。PR に対して自動レビューや Claude Approvals を回している構成に直接関係する修正。

つまりこう使う

  • /code-review や Claude Approvals を CI・PR フローに組み込んでいる場合、v2.1.312 以降は push 直後にレビューコメントが古いコミット由来でないか気にする必要が減る。
