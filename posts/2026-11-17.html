11月16日リリースのv2.1.326から、無人実行や自動化に影響する権限・サンドボックスの仕様変更を中心に選んだ。bypassモードやサンドボックスを使った自動化を組んでいる場合は、動作確認をおすすめする。

この号の内容

  1. bypass permissionsモードでも、一部のツール呼び出しは確認を求められる・拒否されるようになった
  2. サンドボックス化されたコマンドが、ホーム配下の機微なフォルダへの書き込みをデフォルトで拒否するようになった
  3. VS Code拡張に`claudeCode.promptSuggestions`設定が追加され、プロンプト提案をオフにできる
  4. `/plugin`のアンインストール・削除・切り替えの確認が、矢印キー+Enterで選ぶリスト形式に変更
  5. プラグインのアンインストール時、MCPバンドル（`.mcpb`・`.dxt`）から展開されたファイルも削除されるように
  6. `--allowedTools`・`--disallowedTools`・`--tools`の値に不完全なルールがあると、起動時に警告が出るように
注意点

bypass permissionsモードでも、一部のツール呼び出しは確認を求められる・拒否されるようになった

v2.1.326で、bypass permissionsモード（--dangerously-skip-permissionsなど）で動かしている場合でも、一部のツール呼び出しについては承認を求められるようになった。誰も確認に答えられない無人実行の環境では、そのまま拒否される。これまではbypassモードであれば原則すべてのツール呼び出しが無条件に通っていた。

つまりこう使う

  • bypassモードでCI・スケジュールタスク・バックグラウンドエージェントなどを無人実行している場合、これまで通らなかった確認待ち・拒否で処理が止まっていないか、次の実行結果を確認する。
  • 止まっていた場合は、該当のツール呼び出しをpermissions.allowに個別に許可ルールとして追加する必要がある。
  • Claude Code Changelog (v2.1.326)
注意点

サンドボックス化されたコマンドが、ホーム配下の機微なフォルダへの書き込みをデフォルトで拒否するようになった

v2.1.326で、macOS・Linux・WSL上でサンドボックス化されたコマンドが、ホームディレクトリ配下の一部の機微なフォルダに書き込めなくなった。これまで動いていたサンドボックス内のスクリプトが、該当フォルダへの書き込みで失敗するようになる可能性がある。

つまりこう使う

  • サンドボックス内のコマンドが特定のホーム配下フォルダへの書き込みで失敗するようになった場合、user設定またはmanaged設定のsandbox.filesystem.allowWriteにそのパスを追加すると書き込みを許可できる。
  • Claude Code Changelog (v2.1.326)
ワークフロー

VS Code拡張に`claudeCode.promptSuggestions`設定が追加され、プロンプト提案をオフにできる

v2.1.325で追加された、Tabキーで次のプロンプト候補を受け入れられる機能に対して、v2.1.326でVS Code拡張にclaudeCode.promptSuggestions設定が追加された。これをオフにすると、プロンプト提案の表示自体を止められる。

つまりこう使う

  • VS Codeのsettings.jsonに"claudeCode.promptSuggestions": falseを追加すると、入力中にプロンプト候補が出なくなる。
  • Claude Code Changelog (v2.1.326)
Tips

`/plugin`のアンインストール・削除・切り替えの確認が、矢印キー+Enterで選ぶリスト形式に変更

v2.1.326で、/pluginのアンインストール・削除・マーケットプレイス切り替えの確認が、矢印キーとEnterで選ぶリスト形式に変わった。これまで使えたy・n・uのキー入力では答えられなくなっている。

つまりこう使う

  • /pluginでプラグインをアンインストールや切り替えをする際は、キーボードのy/n/uではなく矢印キーで選択肢を選び、Enterで確定する。Escでキャンセルできる。
  • Claude Code Changelog (v2.1.326)
エコシステム

プラグインのアンインストール時、MCPバンドル（`.mcpb`・`.dxt`）から展開されたファイルも削除されるように

v2.1.326で、プラグインをアンインストールすると、そのプラグインが持つMCPバンドル（.mcpb・.dxt）から展開されたファイルも一緒に削除されるようになった。ただし、同じバンドルを別のプラグインも使っている場合は削除されない。

つまりこう使う

  • 特別な操作は不要。プラグインを入れ替えたり整理したりする運用でも、MCPバンドルの展開ファイルがディスクに残り続ける心配が減る。
  • Claude Code Changelog (v2.1.326)
Tips

`--allowedTools`・`--disallowedTools`・`--tools`の値に不完全なルールがあると、起動時に警告が出るように

v2.1.326で、--allowedTools・--disallowedTools・--toolsに渡した値の中に、完全なルールの形になっていないエントリがあると、起動時に警告が表示されるようになった。

つまりこう使う

  • CLIフラグでツールの許可・拒否リストを渡しているスクリプトがある場合、起動時にこの警告が出たら、該当エントリがToolやTool(param:value)のような完全な形式になっているか見直す。
  • Claude Code Changelog (v2.1.326)
