注意点

`--continue` がツール呼び出し失敗の再試行切れ後に以前の会話を失う不具合を修正（v2.1.314のリグレッション）

v2.1.318 で修正。壊れた形式のツール呼び出しが発生し、その再試行が上限に達して終了した場合、--continue で再開すると直前までの会話が失われてしまうことがあった。これは v2.1.314 で入ったリグレッションで、今回で直っている。

つまりこう使う

  • v2.1.314〜317 の間に --continue で会話が消えたように見えたことがあれば、不具合が原因だった可能性が高い。v2.1.318 以降に更新すれば解消される。

ワークフロー

Ctrl+C でプロンプトの入力中テキストを消すと、実行中のバックグラウンドエージェントまで全部止まっていた不具合を修正

v2.1.317 で修正。プロンプトに入力した文字列を消すだけのつもりで Ctrl+C を押すと、実行中の全バックグラウンドエージェントまで一緒に停止してしまう不具合があった。修正後は、入力テキストのクリアと実行中エージェントの停止が分離される。

つまりこう使う

  • バックグラウンドでサブエージェントや Workflow を走らせながら、別の指示を打ち直すために Ctrl+C で入力を消す、という使い方をしている場合は v2.1.317 以降に更新する。これまでは意図せずエージェントを巻き込んで止めていた可能性がある。
  • Claude Code changelog (v2.1.317)
注意点

Grep/Glob が検索のタイムリミットに達したとき、部分的な結果を完全な結果として扱ってしまう不具合を修正

v2.1.317 で修正。Grep や Glob の検索が内部のタイムリミットに達して途中で打ち切られた場合でも、これまでは Claude がその結果を「全件探索済み」として扱ってしまうことがあった。修正後は、打ち切られた検索結果を部分的なものとして正しく認識する。

つまりこう使う

  • 巨大なリポジトリでの網羅的な Grep/Glob 検索（「◯◯を全部探して」系の指示）の結果が、実は一部しか見ていなかったのに「見つかりませんでした」と報告されていた可能性がある。v2.1.317 以降に更新した上で、重要な「該当なし」判定は結果の件数や表示を見て疑ってかかるとよい。
  • Claude Code changelog (v2.1.317)
ワークフロー

Workflow ツールを usage limit 後に resume したとき、完了済みのエージェントまで再実行されてしまう不具合を修正

v2.1.318 で修正。Workflow ツールが usage limit に当たって中断し、limit のリセット後に resume されたとき、すでに完了していたはずのエージェント呼び出しまで再実行されてしまう不具合があった。resumeFromRunId によるキャッシュ再利用が、usage limit 経由の resume では効いていなかったことになる。

つまりこう使う

  • 大きめの Workflow を実行中に usage limit に当たって自動 resume された経験がある場合、v2.1.317 以前では完了済みのエージェントが余分に再実行され、トークンを使い直していた可能性がある。v2.1.318 以降に更新すれば、resume 時に完了済みの agent() 呼び出しは再実行されずキャッシュから復元される。
  • Claude Code changelog (v2.1.318)
Tips

終了時の「Resume this session with」ヒントが、起動時のフラグを `--resume` の前に並べて表示するように改善

v2.1.317 で改善。セッション終了時に表示される再開コマンドのヒントが、これまでは単に claude --resume <id> のような形だったが、改善後は起動時に付けていたフラグ（例: --chrome、--debug）を --resume の前に並べて表示するようになった。

つまりこう使う

  • --chrome や --debug など普段からフラグ付きで claude を起動している場合、セッション終了時に出るヒントをそのままコピペすれば、同じフラグ構成で再開コマンドが組み立てられる。フラグを付け忘れて再開してしまうミスが減る。
  • Claude Code changelog (v2.1.317)
Tips

`claude -p` や SDK での非対話実行時、内容に変更がなければ `~/.claude.json` を毎回書き直さなくなった

v2.1.318 で改善。claude -p や Agent SDK を使った非対話実行では、これまで実行ごとに ~/.claude.json を無条件で書き直していたが、改善後は内容に変化がない場合は書き込み自体をスキップするようになった。

つまりこう使う

  • CI や自動化スクリプトから claude -p を高頻度に呼んでいる場合、v2.1.318 以降では不要なディスク書き込みが減る。ネットワークホームディレクトリ上で ~/.claude.json を使っている環境では、書き込み競合によるトラブルも減らせる。
