POWERUP INFO / VOL.51
2026.11.09

3日間扱ってきたv2.1.319から、まだ載せていなかった残りの項目をまとめた。テレメトリやフィーチャーフラグを切っている環境でauto modeを使っている場合は挙動変化の確認を。セキュリティ関連の修正2件と、地味だが見やすくなった表示系の変更も合わせて紹介する。

この号の内容

  1. テレメトリ/フィーチャーフラグを無効化した環境では、auto modeが組み込み分類器にフォールバックしなくなった
  2. 自動編集/auto modeで`sed`コマンドが権限チェックをスキップできてしまう不具合と、`/rewind`のシンボリックリンク経由のファイル復元・削除を修正
  3. Claude apps gateway利用者向けに、`/usage`で当日・今週・今月の支出を表示できるように
  4. ターミナルの`/context`表示が各リスト最大10行に整理、`/model`ピッカーの古いモデルは「More models」にまとめられる
  5. `/clear`が実行中のバックグラウンドエージェント・チームメイト・ワークフローまで停止してしまう不具合を修正
注意点

テレメトリ/フィーチャーフラグを無効化した環境では、auto modeが組み込み分類器にフォールバックしなくなった

これまでテレメトリやフィーチャーフラグを無効にした環境（LLMゲートウェイ経由を含む）でauto modeを使っていた場合、サーバー側で確認できないアクションは組み込みの分類器が代わりに判定していた。v2.1.319でこのフォールバックが廃止され、サーバー側で確認できないアクションはそのまま確認を求められるか、拒否されるようになった。Bedrock・Vertex・Foundry経由の場合は変更なし。

LLMゲートウェイ経由でサーバー側チェックを使いたい場合、CLAUDE_CODE_AUTO_MODE_SERVER=1を設定する必要があるが、管理設定でCLAUDE_CODE_DISABLE_EXPERIMENTAL_BETASが設定されている場合はそちらも有効になる。

つまりこう使う

  • テレメトリやフィーチャーフラグを切った環境でauto modeを使っている場合、更新後に確認プロンプトや拒否が増えていないか確認する
  • これまでの組み込み分類器による判定を維持したい場合はCLAUDE_CODE_AUTO_MODE_SERVER=0を設定する
  • LLMゲートウェイ経由でサーバー側チェックを有効にしたい場合はCLAUDE_CODE_AUTO_MODE_SERVER=1を設定する（CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETASが設定済みなら必須）
  • Claude Code changelog (v2.1.319)
注意点

自動編集/auto modeで`sed`コマンドが権限チェックをスキップできてしまう不具合と、`/rewind`のシンボリックリンク経由のファイル復元・削除を修正

v2.1.319でセキュリティ関連の不具合が2件修正された。1つは、自動編集モード（acceptEdits）やauto modeが有効な状態で、sedコマンドの書き方次第では本来必要な権限チェックを回避できてしまう不具合。もう1つは、/rewindがディレクトリのシンボリックリンクを経由して、意図した範囲外のファイルを復元・削除できてしまう不具合。

つまりこう使う

  • 自動編集モードやauto modeでsed -iなどを多用している場合、更新すればこの回避ルートはふさがれる。特別な設定変更は不要
  • /rewindでチェックポイントに戻す運用をしている場合も、更新するだけで対策になる
  • Claude Code changelog (v2.1.319)
新機能

Claude apps gateway利用者向けに、`/usage`で当日・今週・今月の支出を表示できるように

Claude apps gatewayを使っていて、個人の支出上限が設定されていない開発者向けに、/usageで当日・今週・今月の支出額を確認できるようになった。ゲートウェイ自体もv2.1.319以降である必要がある。合わせて、クラウドセッションでプラン上限を表示できない場合はclaude.aiのSettings → Usageへのリンクが出るようにもなった。

つまりこう使う

  • Claude apps gatewayを使っていて支出上限の設定がない場合、ゲートウェイ側もv2.1.319以降に更新すれば/usageでその日・週・月の支出が見られるようになる
  • 個人で使う分にはゲートウェイ管理者側の対応が前提になるので、社内でゲートウェイを運用している場合はバージョンを確認するとよい
  • Claude Code changelog (v2.1.319)
Tips

ターミナルの`/context`表示が各リスト最大10行に整理、`/model`ピッカーの古いモデルは「More models」にまとめられる

/contextは、Claudeが読むテーブルを短く保つように変更された。各リストは行数の大きい上位10件のみを保持し、オンデマンドで読み込まれるMCPツールは呼び出されるまでサーバーごとに1行にまとめて表示される。

/modelピッカーも整理され、古いモデルは現在のモデルの直後に並ぶのではなく「More models」という行にまとめられるようになった。

つまりこう使う

  • MCPサーバーを多数つないでいる場合、/contextの表示がこれまでより短くなり、どこがコンテキストを食っているか見やすくなっている
  • /modelで古いモデルを選びたいときは、一覧の「More models」を開く
  • Claude Code changelog (v2.1.319)
ワークフロー

`/clear`が実行中のバックグラウンドエージェント・チームメイト・ワークフローまで停止してしまう不具合を修正

これまで/clearを実行すると、会話の履歴を消すだけでなく、実行中のバックグラウンドエージェントやチームメイト、ワークフローのコマンド、さらにそれらが起動したフォアグラウンドのサブエージェントまで一緒に止まってしまっていた。v2.1.319でこの不具合が修正され、/clearは会話の履歴だけを消し、それらのバックグラウンド処理には影響しないようになった。

つまりこう使う

  • 複数のバックグラウンドエージェントやワークフローを並行させながら、メインの会話だけ/clearで整理したい場合、以前は意図せず全部止めてしまっていた。更新後はそうした誤停止が起きなくなる
  • Claude Code changelog (v2.1.319)
