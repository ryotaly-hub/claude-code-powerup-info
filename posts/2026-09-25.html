エコシステム

Claude Docs / Slides がチャットに統合、会話の延長でドキュメント作成・編集ができるように

Anthropic は Claude Cowork を通常のチャットに統合し、あわせて Claude Docs と Claude Slides をベータ公開した。チャットで「議事録をドキュメントにまとめて」のように頼むと、その場で見出しや表を備えた文書が生成され、直接編集できる。スライド作成を頼めば Claude Slides として会話内に展開される。

作成したドキュメントは共同編集リンクで共有でき、Google Docs や Microsoft Word 形式へのエクスポートにも対応する。スライドは PowerPoint または PDF でダウンロードできる。

つまりこう使う

  • claude.ai の通常チャットで「〜をドキュメントにして」と頼むと Claude Docs が生成され、その場で編集できる
  • 「〜のスライドを作って」と頼むと Claude Slides が展開され、PowerPoint / PDF でダウンロードできる
  • 現時点では Pro / Max プランに先行してベータ提供中。Team / Free プランは後日展開される
  • 「Claude Cowork」がClaudeチャットに統合、ドキュメント・スライド作成も可能に（TechnoEdge）
ワークフロー

Cloud Sessions、実行中セッションに別オーナーのリポジトリ（フォーク元など）をあとから接続できるように（v2.1.282）

Cloud Sessions（旧 Claude Code on the web）で、すでに1つのリポジトリに紐づいて実行中のセッションに対し、フォーク元など別オーナーの GitHub リポジトリをあとから追加で接続できるようになった。Slack から始めたセッションでも同じ操作ができる。

あわせて Settings › Connectors › GitHub に、Claude GitHub App が自分のアカウントに対してインストール・接続済みかどうかのステータスと、未接続時の接続手順が表示されるようになった。

つまりこう使う

  • フォーク元リポジトリの Issue や PR を見ながら作業したいときは、実行中のクラウドセッションのリポジトリメニューから別オーナーのリポジトリを追加接続する
  • GitHub 連携が効いているか不安なときは Settings › Connectors › GitHub でアプリの接続状況を確認する
  • Release v2.1.282 · anthropics/claude-code
Tips

`maxProseWidth` 設定で、ワイドターミナルでの本文の折り返し幅を制限できる（v2.1.282）

横に広いターミナルで Claude Code を使うと、応答の地の文が画面幅いっぱいに折り返されて読みにくくなることがあった。maxProseWidth 設定を追加すると、地の文だけ読みやすい幅に制限した状態で折り返される。表やコードブロックはこれまでどおり全幅で表示される。

つまりこう使う

  • ワイドモニターでターミナルを大きく開いて使っているなら、settings.json に "maxProseWidth" を追加して文字数を指定する
  • 表・コードブロックの見やすさはそのままに、地の文だけ読みやすくしたい場合に試す
  • Claude Code Changelog（公式）
Tips

Cloud Sessions のモデルメニューに Fast mode の切り替えスイッチが追加された（v2.1.281）

Cloud Sessions の入力欄にあるモデルメニューから、Fast mode の ON / OFF を直接切り替えられるようになった。これまでコマンドや設定経由でしか切り替えられなかった Fast mode に、クラウド側からもワンタップで手が届く。

つまりこう使う

  • Cloud Sessions で応答速度を優先したいときは、入力欄のモデルメニューを開いて Fast mode を有効にする
  • 精度を優先したいターンに戻ったら、同じメニューから Fast mode を切る
  • Claude Code Changelog（公式）
注意点

起動時通知・`/status`・`claude doctor` に、無効化されたテレメトリ変数の一覧が出るようになった（v2.1.282）

プロジェクトの設定ファイルにテレメトリ関連の環境変数が書かれていても、他の設定と衝突して実際には無視されていたり、テレメトリ自体がオフになっていたりするケースがあった。v2.1.282 では、そうした「効いていない」テレメトリ変数の一覧が起動時の通知と /status・claude doctor に表示されるようになり、気づかないまま収集できていなかった状態を早期に発見できる。

つまりこう使う

  • チームでテレメトリ収集の設定をしているなら、更新後に一度起動して通知が出ないか確認する
  • 収集できていない疑いがあるときは /status か claude doctor を実行し、無効化されている変数がないか見る
  • Claude Code Changelog（公式）
