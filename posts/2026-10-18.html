POWERUP INFO / VOL.29
2026.10.18

v2.1.302（10月16日リリース）から、まだ取り上げていない項目をまとめる。デスクトップアプリ・VS Code 拡張でのサブエージェントの実行場所が整理され、ToolSearch 経由で読み込むツールのキャッシュ効率が改善した。Claude Design のスタンドアロン版が年末で終了する予告にも注意したい。

この号の内容

  1. デスクトップアプリ・VS Code 拡張、メイン会話のサブエージェントは常にバックグラウンド実行に。サブエージェント自身が呼ぶ Agent はフォアグラウンドがデフォルトに
  2. ToolSearch 経由で読み込むツールやコンパクション後の再読み込みで起きていたプロンプトキャッシュミスを修正
  3. auto mode のサーバー側分類器、会話が長すぎて安全チェックできない場合はコンパクションされるように。以前は全ツール呼び出しが拒否されていた
  4. `/design-sync`・`/design-login` に通知追加。スタンドアロン版 Claude Design（claude.ai/design）は2026年12月14日に終了予定
  5. git 2.56 以降で worktree isolation の作成・再開が失敗する不具合を修正（存在しないディレクトリを指す `.git` ファイルが原因）
  6. プラグインを多数有効にしている環境での起動時間が改善。Windows で特に効果が大きい

デスクトップアプリ・VS Code 拡張、メイン会話のサブエージェントは常にバックグラウンド実行に。サブエージェント自身が呼ぶ Agent はフォアグラウンドがデフォルトに

これまでデスクトップアプリと VS Code 拡張では、メイン会話から呼ぶサブエージェントをバックグラウンドで動かすかどうかを Claude が判断していたが、v2.1.302 でターミナルと同様に常にバックグラウンド実行になるよう変更された。

一方、サブエージェントがさらに自分で呼ぶ Agent 呼び出し（claude -p・Agent SDK・デスクトップアプリ・VS Code 拡張のいずれでも）は、今回からフォアグラウンド実行がデフォルトになった。

つまりこう使う

  • デスクトップアプリ・VS Code 拡張でメインの会話からサブエージェントに作業を委任するとき、裏で勝手に動くか手前で動くかを気にしなくてよくなった。常にバックグラウンドで進み、会話は止まらない
  • Agent SDK でサブエージェントにさらに Agent を呼ばせる構成を組んでいる場合、その内側の Agent 呼び出しは今回からフォアグラウンド実行が既定になる点に注意する。裏で動かしたいなら明示的にバックグラウンド指定が必要になる
  • Claude Code Changelog
Tips

ToolSearch 経由で読み込むツールやコンパクション後の再読み込みで起きていたプロンプトキャッシュミスを修正

セッション中に追加されたツールを、ToolSearch（deferred tools）経由で改めて読み込んだときや、コンパクションのあとに再読み込みしたときにプロンプトキャッシュがミスしてしまう不具合が修正された。これまでは同じツールを再度読み込むたびにキャッシュが効かず、余計なトークンコストと待ち時間が発生していた。

つまりこう使う

  • deferred tools を ToolSearch で都度読み込みながら進めるセッションや、長時間のセッションでコンパクションを挟む運用をしている場合、v2.1.302 以降ではキャッシュが効くようになっているぶん応答が速く・安く済む
  • 特別な設定変更は不要。バージョンを v2.1.302 以降に上げるだけで効く
  • Claude Code Changelog
ワークフロー

auto mode のサーバー側分類器、会話が長すぎて安全チェックできない場合はコンパクションされるように。以前は全ツール呼び出しが拒否されていた

auto mode（権限確認を分類器が代行するモード）で、会話が長すぎて安全チェック自体が行えないケースがあった。これまではそのたびにチェック対象のツール呼び出しがすべて拒否される挙動だったが、v2.1.302 からは会話がコンパクションされてから分類器にかけられるよう改善された。

つまりこう使う

  • auto mode で長時間の会話を続けていてツール呼び出しが急に全部拒否されるようになった、という状況に遭遇していた場合、v2.1.302 以降ではその場面でコンパクションが走って処理が続行されるようになっている
  • 対処は特に不要。バージョンを上げておけば自動的にこの挙動になる
  • Claude Code Changelog
注意点

`/design-sync`・`/design-login` に通知追加。スタンドアロン版 Claude Design（claude.ai/design）は2026年12月14日に終了予定

/design-sync と /design-login の実行時に、claude.ai/design のスタンドアロン版が2026年12月14日で終了する旨の通知が表示されるようになった。Claude Code 側のデザイン連携機能自体が終わるわけではなく、ブラウザ単体で開くスタンドアロンの Claude Design が終了するという告知である。

つまりこう使う

  • claude.ai/design をブラウザから単独で開いて作業している場合、12月14日より前に Claude Code 経由の /design ワークフローに移行しておく
  • /design-sync や /design-login を使っていて今回の通知を見た場合、移行の必要があるかどうかをチームで確認しておくとよい
  • Claude Code Changelog
注意点

git 2.56 以降で worktree isolation の作成・再開が失敗する不具合を修正（存在しないディレクトリを指す `.git` ファイルが原因）

git 2.56 以降を使っている環境で、worktree を指す .git ファイルが存在しないディレクトリを参照している場合に、worktree isolation での worktree の作成・再開が拒否されてしまう不具合があった。v2.1.302 で修正されている。

つまりこう使う

  • git 2.56 以降の環境で worktree isolation を使っていて作成・再開に失敗していた場合、v2.1.302 以降へ更新すれば解消する
  • 更新後も同じ場所で失敗する場合は、該当の worktree ディレクトリ自体が壊れている可能性があるので、git worktree list で状態を確認する
  • Claude Code Changelog
Tips

プラグインを多数有効にしている環境での起動時間が改善。Windows で特に効果が大きい

プラグインを多数有効にしている場合の起動時間が改善された。プラグインのコマンド・サブエージェント定義ファイルを読み込む際のファイルシステム呼び出し回数が大幅に減り、特に Windows 環境で効果が大きいとされている。

つまりこう使う

  • 複数のプラグインを有効にしていて起動が遅いと感じていた場合、v2.1.302 以降に更新するだけで改善が見込める。設定変更は不要
  • Windows でプラグインを多用している場合は特に起動時間の短縮を実感しやすい
  • Claude Code Changelog
