新機能

作業ディレクトリ外への書き込みを拒否する `permissions.blockWritesOutsideWorkingDirectories` を追加

v2.1.314 で追加された設定。Write・Edit・NotebookEdit は、デフォルト・auto・acceptEdits などどの権限モードで動いていても、作業ディレクトリ外のパスへの書き込みを拒否するようになる。

モノレポや複数の worktree をまたいで作業していて、意図せず別ディレクトリのファイルを編集してしまう事故を防ぎたい場合に有効。

つまりこう使う

  • settings.json に {"permissions": {"blockWritesOutsideWorkingDirectories": true}} を追加すると、作業ディレクトリ外への Write/Edit/NotebookEdit が権限モードに関係なく拒否されるようになる。
  • Claude Code changelog（v2.1.314）
ワークフロー

`ultrathink` が対応モデルで自動的に xhigh effort になる

v2.1.311 で、インタラクティブ端末で ultrathink と打つと、Opus 5.5・Sonnet 5.5・Haiku 5.5・Fable 5.1 では effort が自動的に xhigh に設定されるようになった。

これまでは ultrathink と /effort xhigh を別々に意識する必要があったが、今後は ultrathink ひとことで最大の思考深度に切り替わる。

つまりこう使う

  • 難しいバグ調査や設計検討のときは、プロンプトの頭に ultrathink と書くだけでよい。対応モデルなら effort が xhigh まで自動で上がる。
  • Claude Code changelog（v2.1.311）
Tips

VS Code・Claude Desktop の Code タブにアイドル時コンパクションを追加

v2.1.314 で、VS Code 拡張や Claude Desktop の Code タブに、セッションがアイドル状態のときにバックグラウンドでコンテキストをコンパクションする機能が追加された。

会話に戻ってきた直後にコンパクションが走って待たされる場面が減る。

つまりこう使う

  • 特別な操作は不要。長時間アイドルにしたセッションに戻ったとき、以前よりコンパクション待ちが発生しにくくなっているはず。
  • Claude Code changelog（v2.1.314）
Tips

Bash ツールのシェルが継承した `which` のエイリアス・関数をクリアするように

v2.1.314 で、Claude Code の Bash ツールが起動するシェルは、ユーザーの .bashrc 等から継承した which 向けのエイリアスや関数をクリアして実行されるようになった。

これまでは環境によって which npm などが別名解決されてしまい、Claude が実際とは違うパスを参照することがあった。

つまりこう使う

  • 手元の shell で which をラップする alias や function を定義していても、Claude Code の Bash ツール内では本来の which の結果がそのまま返ると理解しておけばよい。
  • Claude Code changelog（v2.1.314）
注意点

`claude ultrareview` はワークスペースの信頼確認が必須に、CI では `--trust-workspace` が必要

v2.1.309 で、claude ultrareview の実行時にワークスペースの信頼確認が必須になった。

対話なしで動かしているスクリプトや CI では、この確認で止まってしまうため、フラグか環境変数で明示的に許可する必要がある。

つまりこう使う

  • CI で claude ultrareview を使っている場合は claude ultrareview --trust-workspace 123 のように渡す。
  • 環境変数で確認を止めたい場合は CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 を設定する。
  • Claude Code changelog（v2.1.309）
注意点

`sed -i` は通常の Bash 権限プロンプトを通るようになり、`/rewind` で復元されなくなった

v2.1.309 で、sed -i によるファイル書き換えは Edit ツールと同じ特別扱いではなく、通常の Bash コマンドとして権限プロンプトの対象になった。

あわせて、この経由での変更は /rewind の対象外になったため、sed -i で書き換えた内容は Rewind メニューから元に戻せない。

つまりこう使う

  • sed -i で一括置換した後に元に戻したくなった場合、/rewind には頼れない。git の diff から手動で戻す必要がある。
  • 破壊的な一括置換をする前に、git で commit しておくか diff を確認してから実行すると安全。
  • Claude Code changelog（v2.1.309）
