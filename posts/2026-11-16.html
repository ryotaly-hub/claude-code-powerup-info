新機能

Vertex AI経由の利用で、fast modeがglobal/us/euリージョンに拡大

v2.1.322で、Google Cloud Vertex AI経由でClaude Codeを使う場合に、fast modeがglobal・us・euの各リージョンで利用できるようになった。Vertex側がfast modeのリクエストを受け付けない場合は、Claude Codeが自動で通常速度にフォールバックする。

つまりこう使う

  • Vertex AI経由でClaude Codeを使っている場合、特別な設定変更をしなくても、該当リージョンであればfast modeの速度向上がそのまま効くようになる。
  • Claude Code Changelog
ワークフロー

信頼していないリポジトリへの読み取り専用gitコマンドも確認を求めるように

v2.1.325から、今のプロジェクトでも--add-dirで信頼済みに登録した追加ディレクトリでもないリポジトリに対してgit logやgit showのような読み取り専用コマンドを実行する際も、確認が求められるようになった。これまでは読み取り専用であることを理由に確認なしで実行されていた。

つまりこう使う

  • 複数リポジトリを横断して調べ物をする運用がある場合、確認ダイアログを都度閉じる代わりに、起動時の--add-dir <path>でそのリポジトリを追加ディレクトリとして登録しておくと確認なしで読み取り専用コマンドが動く。設定ファイルのadditionalDirectoriesでは同じ扱いにならない点に注意。
  • Claude Code Changelog
エコシステム

`claude plugin validate`がプラグインのTypeScript製hooksを型チェック、`--strict`で失敗させられる

v2.1.323で、claude plugin validateがプラグインの提供するTypeScript製hooksモジュールに対して型チェックを行うようになった。--strictを付けると、型エラーが見つかった時点でコマンド自体が失敗する。

つまりこう使う

  • プラグインを配布する前にCIで検証している場合は、claude plugin validate --strictを組み込むと、hooksの型の不整合を実行時エラーになる前にCIで止められる。
  • Claude Code Changelog
注意点

`claude agents`で`--verbose`等と併用時に`--permission-mode`・`--model`・`--effort`・`--agent`が無視される不具合が修正

v2.1.321で、claude agentsコマンドに--verboseのような別のフラグを同時に指定すると、--permission-mode・--model・--effort・--agentの指定が無視されてしまう不具合が修正された。

つまりこう使う

  • これまでclaude agents --model opus --verboseのような組み合わせでモデル指定が効いていなかった場合、v2.1.321以降では直っているので、同じ使い方をしているスクリプトがあれば一度動作を確認しておくとよい。
  • Claude Code Changelog
注意点

`/security-review`が実行前に確認を求めるようになった

v2.1.323から、/security-reviewコマンドは実行前にユーザーの確認を求めるようになった。これまでは確認なしにそのまま実行されていた。

つまりこう使う

  • CIやスケジュールタスクなど無人環境で/security-reviewを自動実行している場合、この確認待ちで処理が止まる可能性がある点に注意する。
  • Claude Code Changelog
Tips

バックグラウンドセッションで`/logout`すると、同じマシン上の全セッションがログアウトされる

v2.1.323から、バックグラウンドセッションで/logoutを実行すると、同じマシン上で動いているすべてのセッションがログアウトされるようになった。

つまりこう使う

  • 複数セッションを同じマシンで並行させている場合、そのうち1つだけをログアウトしたいつもりで/logoutを打つと他のセッションも巻き込まれる。実行前に影響範囲を把握しておく。
  • Claude Code Changelog
