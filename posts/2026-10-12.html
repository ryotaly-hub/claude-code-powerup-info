新機能

`CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL` が追加、Workflow tool のエージェントだけ全部同じモデルで動かせるように（v2.1.296）

Workflow tool（/workflows などで複数のサブエージェントを動かす仕組み）が起動するエージェントは、これまで各エージェントの個別設定どおりのモデルで動いていた。v2.1.296 からは環境変数 CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL にモデル名を設定すると、その Workflow 内の全エージェントが指定したモデルで統一して動くようになる。Workflow の外で動く通常のサブエージェント（Agent tool 経由など）は、この設定の影響を受けず従来どおり個別のモデルを使う。

つまりこう使う

  • コストやレイテンシを揃えたい検証時は、CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL=claude-sonnet-5-5 のように設定してから Workflow を実行すると、途中のエージェントごとのモデル差異を気にせず結果を比較できる
  • Claude Code Changelog — v2.1.296
注意点

Windows: Git Bash の `rm -rf /c/Users/<name>` が bypass permissions モードでも確認なしに実行されていた不具合を修正（v2.1.296）

Windows の Git Bash 環境で rm -rf /c/Users/<name> のような危険なコマンドを実行すると、bypassPermissions モード下では確認を求めずそのまま実行されてしまう不具合があった。v2.1.296 でこの不具合が修正され、bypass permissions モードでもこの種のコマンドには確認が入るようになった。

つまりこう使う

  • Windows で bypassPermissions モードや --dangerously-skip-permissions を使っている場合、更新後は危険な rm -rf 系コマンドで確認プロンプトが出ることを前提にしておく
  • Claude Code Changelog — v2.1.296
Tips

Windows: PowerShell の長文コマンドが約1KBを超えると常に権限確認を求められていた不具合を修正、許可ルールが32KBまで効くように（v2.1.296）

Windows で PowerShell コマンドを実行する際、コマンド文字列が約1KBを超えると、許可ルールや読み取り専用判定が機能せず毎回確認を求められていた。v2.1.296 からはこの上限が32KBまで拡大され、長いコマンドでも許可ルールや読み取り専用判定が正しく適用されるようになった。

つまりこう使う

  • Windows で長めの PowerShell コマンドを許可ルール（allow）に登録している場合、今後はコマンドが長くても確認プロンプトなしで実行されるようになったはずか確認する
  • Claude Code Changelog — v2.1.296
注意点

VS Code: Claude in Chrome が `@browser` 接続時も含め、セッションごとにブラウザ操作の確認を求めるように（v2.1.296）

VS Code 拡張の Claude in Chrome は、これまで @browser で接続したセッションではブラウザ操作の確認を求めないことがあった。v2.1.296 からは、ターミナルと同様にどのセッションでも最初のブラウザ操作時に確認を求めるよう統一された。一度そのセッションでサイトを許可すれば、以降は同じセッション内で再度聞かれることはない。

つまりこう使う

  • VS Code で Claude in Chrome を使っている場合、更新後は新しいセッションごとに最初のブラウザ操作で確認が入ることを想定しておく。繰り返し同じサイトを使うなら最初の確認で許可しておけばそのセッション中は聞かれない
  • Claude Code Changelog — v2.1.296
Tips

コードの多い会話での transcript 切替（Ctrl+O）のレスポンスが改善、構文ハイライト済みコードブロックをキャッシュ（v2.1.296）

Ctrl+O で表示を切り替えるトランスクリプト表示は、コードブロックの多い長い会話で切替時に重くなることがあった。v2.1.296 で構文ハイライト済みのコードブロックをキャッシュするようになり、同じ会話内での切替が速くなった。

つまりこう使う

  • 特別な設定は不要。コード中心の長い会話で Ctrl+O の切替が以前より速くなっているはずなので、重さを感じていた場合は更新後の挙動を確認するとよい
  • Claude Code Changelog — v2.1.296
Tips

auto mode で判定不能だったツール呼び出しが、赤いエラーではなくグレーの「Not run」表示になるように（v2.1.296）

auto mode で許可判定（安全チェック）が答えを出せなかったために実行されなかったツール呼び出しは、これまで赤いエラー行として表示され、本物の失敗と見分けにくかった。v2.1.296 からは、こうしたケースはグレーの「Not run」行として表示され、エラーと区別できるようになった。

つまりこう使う

  • auto mode 使用中にグレーの「Not run」表示を見かけたら、ツールの実行自体が失敗したわけではなく、安全チェックが判定できずスキップされたことを意味すると理解しておけば、無駄な原因調査をしなくて済む
  • Claude Code Changelog — v2.1.296
