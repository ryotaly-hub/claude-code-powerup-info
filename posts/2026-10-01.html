ワークフロー

`verify` という名前のスキルがあれば、コミット直前に自動実行されるように（v2.1.286）

コミットガイダンスが改善され、プロジェクトまたはユーザーのスキルに verify という名前のものが登録されていると、Claude はコミットの直前にそれを実行するよう指示されるようになった。対象はコードの変更を伴うコミットで、ドキュメントのみ・テストのみのコミットは対象外。

テスト・lint・型チェックなど「コミット前に必ず確認したいこと」をスキルとしてまとめておけば、Claude 任せの場面でも検証漏れを防ぎやすくなる。

つまりこう使う

  • プロジェクトの .claude/skills/verify/SKILL.md（またはユーザースキル）に、テスト・lint・型チェックなど確認したいコマンドをまとめておく
  • 以降、Claude が git commit する直前にこのスキルを自動実行する（docs-only・tests-only のコミットは対象外）
  • Claude Code Changelog
Tips

`--bare` 起動が名実ともに「素」になった（v2.1.286）

--bare フラグの挙動が変更され、コマンドラインで明示的に指定した MCP サーバーだけが接続されるようになった。モデルへのシステムリマインダー送信やバックグラウンドタスクの開始も一切行われない。あわせて --bare 下ではシェルコマンドがタイムアウトに達した場合、バックグラウンドに逃がさずそこで停止するようになった。

評価ハーネスやベンチマーク、再現性が重要なスクリプト実行で、余計なコンテキストや挙動に邪魔されたくない場面に向く。

つまりこう使う

  • 最小構成で再現性を取りたいスクリプトや CI では claude --bare を使う
  • 必要な MCP サーバーだけをコマンドライン引数で明示的に指定する
  • Claude Code Changelog
Tips

権限確認プロンプトが複数たまったとき「2 of 5」のように件数表示されるように（v2.1.286）

権限確認のリクエストが連続して積み上がった場合、プロンプトに「2 of 5」のような進捗表示が追加された。あと何件確認が残っているかが一目でわかるようになる。

つまりこう使う

  • 複数ファイルへの一括編集などで確認プロンプトが連続するとき、画面の件数表示で残りの数を確認できる
  • Claude Code Changelog
注意点

モデルフォールバックでコンテキストウィンドウが1M→200Kトークンに縮むとき、通知で明記されるように（v2.1.286）

フォールバック先のモデルによってコンテキストウィンドウが 1M トークンから 200K トークンに縮小するケースで、そのことがフォールバック通知や autocompact のスラッシングエラーに明記されるようになった。フォールバックが発生したとき、何が起きているか気づきやすくなる。

つまりこう使う

  • フォールバック通知にコンテキストウィンドウの縮小が明記されていたら、長い会話では /compact や /clear を早めに検討する
  • Claude Code Changelog
エコシステム

VS Code 拡張に Bookmarks が追加、Claude の回答を保存してサイドパネルで参照できる（v2.1.286）

VS Code 拡張に Bookmarks 機能が追加された。Claude の回答を保存しておくと、専用の Bookmarks サイドパネルに一覧表示され、後から参照できる。

つまりこう使う

  • 残しておきたい回答やコード例が出てきたら Bookmark して、サイドパネルからいつでも呼び出す
