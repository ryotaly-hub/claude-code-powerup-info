注意点

IDEのターミナルから起動したとき、Claude Codeが拡張機能を自動インストール/自動更新しなくなった

v2.1.318 で変更。これまでVS CodeなどのIDE内蔵ターミナルからclaudeを起動すると、そのIDE用拡張機能を自動でインストール・更新していたが、この挙動が廃止された。今後は拡張機能のインストール・更新は、IDEの外のターミナルから/ideを実行するか、エディタの拡張機能ビューから手動で行う必要がある。

つまりこう使う

  • IDE内蔵ターミナルでclaudeを起動しても拡張機能が入らない/更新されないと感じたら、不具合ではなく仕様変更。外部ターミナルで/ideを実行するか、エディタの拡張機能一覧から手動更新する。

ワークフロー

バックグラウンドサブエージェントのシェルコマンドが、3分経過すると自動でバックグラウンド実行に切り替わるように

v2.1.318 で変更。バックグラウンドで動くサブエージェントが実行するシェルコマンドが3分を超えて動き続けている場合、プロバイダを問わず自動でバックグラウンド実行に移されるようになった。長時間コマンドの実行中にプロンプトキャッシュが切れてしまうのを防ぐための変更。

つまりこう使う

  • ビルドやテストなど数分以上かかるコマンドをバックグラウンドサブエージェントに投げるケースで、以前より途中のキャッシュ切れによる無駄なトークン消費が減る見込み。特に何か設定を変える必要はない。
  • Claude Code changelog (v2.1.318)
Tips

`claude auth status`にclaude.aiログインの期限が表示されるようになり、`claude -p`は期限10日前から警告を出す

v2.1.318 で追加。保存されているclaude.aiのログインがいつ切れるかが、claude auth statusのloginExpiresAt、およびclaude -pのJSON出力のcredential_expires_atとして確認できるようになった。加えてclaude -pのテキスト出力では、ログイン期限の10日前から1行のstderr警告が出るようになる。

つまりこう使う

  • claude -pをCIや自動化スクリプトで使っている場合、claude auth statusを定期的に流してログイン期限を確認しておくと、期限切れによる突然の失敗を事前に察知できる。警告が出たらclaude auth loginやclaude setup-tokenで再認証する。
  • Claude Code changelog (v2.1.318)
注意点

`~/.claude.json`が壊れていても黙ってデフォルトで上書きしていた不具合を修正、復旧方法を表示するように

v2.1.318 で修正。非対話実行（claude -pなど）のとき、~/.claude.jsonが壊れた形式のJSONだと、これまでは黙ってデフォルトの内容で上書きしてしまい、設定が失われていた。修正後は起動自体を失敗させ、ファイルの復旧方法を表示したうえで元のファイルはそのまま残す。また、バックアップがない空の~/.claude.jsonを「破損」と誤判定していた不具合、復旧コマンドが空や壊れたバックアップを指してしまう不具合も合わせて修正された（anthropics/claude-code#87551）。

つまりこう使う

  • ~/.claude.jsonが原因不明のタイミングでリセットされたような経験がある場合、v2.1.318より前のこの不具合が関係していた可能性がある。更新後は、ファイルが壊れていても設定が黒い箱に消えることはなく、復旧手順がその場で案内される。
  • Claude Code changelog (v2.1.318)
新機能

mod作者向けに、`$.model.fork`のサブタスクをセッションのeffortと関係なく`low`固定で実行できるオプションを追加

v2.1.318 で追加。Claude Codeのmod（セッション中にClaude自身が書く拡張）が$.model.forkでちょっとした副タスクを投げるとき、セッション全体のeffortレベルに関わらずlow固定で実行できるeffortオプションが追加された。実行結果には、実際に送られたeffortが報告される。

つまりこう使う

  • mod を書いていて、セッションがhighやxhighで動いていても軽い確認作業だけ安く済ませたい場合、$.model.fork呼び出しにeffort: "low"を指定すればよい。mod を書かない読者には直接の影響はない。
