注意点

Windows: Git Bash が無い環境で `PreToolUse`/`PermissionRequest` フックがすり抜けていた不具合を修正

v2.1.309 で、Windows で "shell": "powershell" を指定した PreToolUse / PermissionRequest フックが、Git Bash がインストールされていない環境だと fail-open（＝チェックをすり抜けて許可されてしまう）していた不具合が修正された。フックでツール呼び出しをブロックする設定をしていても、実際には効いていなかった可能性がある。

合わせて、PowerShell で動くフックのプログラムが終了コード 2 を返したときにブロックされない不具合も直っている。

つまりこう使う

  • Windows + PowerShell シェルで security 目的の PreToolUse/PermissionRequest フックを使っている場合は v2.1.309 以降にアップデートし、意図したブロックが実際に効くか一度確認する。
  • claude-code v2.1.309 release notes
注意点

Windows: PowerShell の `Set-Location`/`cd` に引数を追加したコマンドが自動承認されなくなった

v2.1.309 で、PowerShell の Set-Location や cd が対象を現在のディレクトリにしていても、余分な引数が付いている場合は無条件に自動承認されていた不具合が修正された。今後はそうしたコマンドも通常どおり許可プロンプトが出る。

つまりこう使う

  • Windows でビルドスクリプトやフックの中で cd に追加フラグを渡している場合、アップデート後は許可プロンプトが増える想定でワークフローを組んでおく。
  • claude-code v2.1.309 release notes
ワークフロー

`/rewind` が `/code-review --fix`・サブエージェント・シェルコマンドによる変更も正しく検出するように

v2.1.309 で、/rewind の一覧が、そのターンで /code-review --fix やサブエージェント、シェルコマンド経由でチェックポイント対象のファイルが変更されていても「No code changes」と表示してしまう不具合が修正された。Claude が直接 Edit/Write したときだけでなく、こうした経路での変更も一覧から見えるようになる。

つまりこう使う

  • /code-review --fix やサブエージェントに修正をまとめて任せた後、/rewind を開いてそのターンに「変更あり」と表示されるか確認してから戻す/戻さないを判断する。
  • claude-code v2.1.309 release notes
Tips

ディスク容量不足でコマンドが止まったとき、原因と空き容量を確保すべきフォルダ名が表示されるように

v2.1.309 で、ディスク容量不足のために Bash コマンドが途中で止まったとき、生の ENOSPC エラーの代わりに容量不足であることと、空き容量を確保すべきフォルダ名を示すようになった。一時ファイル用ボリュームの空き容量が無い状態で Claude Code を起動した場合も同様に分かりやすいメッセージが出る。

つまりこう使う

  • 長時間のビルドや大きなファイル出力を伴うコマンドが途中で止まったら、まずこのエラー表示でディスク容量不足かどうかを確認し、該当フォルダを掃除してから再実行する。
  • claude-code v2.1.309 release notes
Tips

`--add-dir` のフォルダに同名スキルがあっても `<folder>:<name>` で呼び分けられるように

v2.1.309 で、--add-dir で追加したフォルダの中のスキルが、既存のスキルと同じ名前のために呼び出せなくなっていた不具合が修正された。今後は名前が衝突した場合、そのスキルは <folder>:<name> という形式で提供され、両方とも使えるようになる。

つまりこう使う

  • --add-dir で別プロジェクトのスキルフォルダを読み込んでいて名前が衝突している場合は、/<folder名>:<スキル名> の形で呼び出す。
  • claude-code v2.1.309 release notes
ワークフロー

auto mode: 作業ディレクトリ外の最初の読み取り前の確認が、シェルコマンドへの影響も明示するように

v2.1.310 で、auto mode が作業ディレクトリ外のファイルへの最初の読み取りを確認する際のプロンプトが改善された。そこで読み取りをブロックすると、以降はシェルコマンドも許可プロンプトを求められるようになる、という影響を事前に示すようになった。

つまりこう使う

  • auto mode を使っていて作業ディレクトリ外のファイル読み取りを確認された場合、ブロックを選ぶとその後のシェルコマンドの挙動も変わる点を踏まえて判断する。
  • claude-code v2.1.310 release notes
